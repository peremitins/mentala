# ТЗ: Выбор тем в онбординге и автоподключение напоминаний

## Summary
- После имени заменить текущий шаг «Что привело вас в Ментала?» на выбор реальных тем терапии и привычек.
- Пользователь выбирает до 5 тем, которые сохраняются как стартовый фокус онбординга.
- После выбора тем показать отдельный экран с предложением включить уведомления.
- Выбранные темы создают активные настройки напоминаний, а системное push-разрешение запрашивается отдельно.
- Сохраняем минимальную обратную совместимость старого `reason/reasons` payload.

## Key Changes
- Онбординг:
  - порядок шагов: `welcome -> name -> topics -> reminders -> age -> gender -> tone -> final`;
  - заголовок выбора: **«Что сейчас важно для вас?»**;
  - подсказка: **«Выберите до 5 тем, с которых хотите начать. Это поможет Ментала точнее подбирать поддержку.»**;
  - группы: **Эмоциональное состояние**, **Полезные привычки**, **От чего хотите отказаться**;
  - источники данных: `THERAPY_TOPICS` и `HABITS_CATALOG`;
  - кнопка продолжения активна при выборе от 1 до 5 тем.
- Экран напоминаний:
  - заголовок: **«Получать напоминания по выбранным темам?»**;
  - текст: **«Напоминания помогают возвращаться к выбранным темам в течение дня и закреплять новые привычки. Частоту и тон можно изменить в настройках.»**;
  - кнопки: **«Включить уведомления»** и **«Не сейчас»**;
  - при включении использовать существующий push-permission flow;
  - при «Не сейчас» продолжать онбординг и после входа показывать предложение включить push.
- Напоминания:
  - для выбранных тем создавать/активировать `notification_preferences`;
  - новые настройки по умолчанию: `enabled=true`, `timesPerDay=2`, `directness=moderate`, `subtype=mixed`, все дни, окно `09:00–22:30`;
  - глобальный дефолт новых напоминаний изменить с `3` на `2`.

## API / Data
- Добавить optional-поле в onboarding DTO:
  - `selectedTopics: Array<{ kind: 'therapy' | 'habits'; entityKey: string }>`;
  - лимит `1..5`, без дублей, только валидные ключи каталогов.
- Старые `reason` / `reasons` не удалять:
  - старый payload должен по-прежнему проходить `/api/user/onboarding/complete`;
  - новый UI старые варианты больше не показывает;
  - legacy-данные использовать только как fallback для совместимости.
- Сервер при завершении онбординга:
  - сохраняет выбранные темы в `users.onboarding.selectedTopics`;
  - продолжает заполнять `user_preferences.onboarding_reasons`;
  - создаёт missing preferences для выбранных тем;
  - существующие preferences не перетирает, кроме гарантии `enabled=true`.

## Test Plan
- DTO:
  - новый `selectedTopics` проходит валидацию;
  - больше 5 тем, дубли и неизвестные ключи отклоняются;
  - старые `reason/reasons` остаются рабочими.
- API:
  - новый онбординг создаёт активные preferences по выбранным темам;
  - повторный submit идемпотентен;
  - существующие пользовательские настройки не теряют расписание;
  - частота новых preferences равна `2`.
- UI:
  - шаг тем корректно группирует therapy/build/quit;
  - лимит выбора работает;
  - экран напоминаний корректно обрабатывает обе кнопки;
  - после онбординга выбранные темы отображаются как включённые на страницах терапии/привычек.
- Regression:
  - текущие пользователи и review-аккаунты не ломаются;
  - старый onboarding payload не падает;
  - push-permission flow остаётся прежним.

## Assumptions
- В онбординге показываем только статичные каталожные темы, без кастомных тем пользователя.
- Сейчас выбранные темы не меняют поведение ИИ-ассистента, но сохраняются для будущей персонализации.
- Если системное разрешение push не выдано, настройки темы остаются включёнными, но UI должен отдельно показывать, что доставка уведомлений требует разрешения.
