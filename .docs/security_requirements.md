# Требования к безопасности и приватности

## Принципы

- Все данные пользователей (сообщения, история, файлы) должны быть зашифрованы.
- Используется end-to-end шифрование: ключи хранятся только на устройствах пользователей.
- Архитектура "Zero-Access": сотрудники компании и администраторы серверов **не имеют доступа** к пользовательским данным.
- Ключи разделяются и хранятся в разных местах, исключая возможность их использования в обход.

## Реализация

1. Все сообщения шифруются перед отправкой на сервер (E2EE).
2. На сервере хранится только зашифрованный контент.
3. Метаданные (таймстемпы, ID сообщений) хранятся отдельно и также защищены.
4. Расшифровка возможна только на устройстве получателя.
5. В случае компрометации серверов данные остаются недоступными.

## Приватность

- История сообщений по умолчанию не сохраняется.
- Пользователь может включить хранение истории, тогда история будет храниться зашифрованной.
- Нет возможности технически расшифровать историю без ключей пользователя.

## Политика компании

- Мы никогда не предоставляем доступ к личным сообщениям пользователей.
- Даже при юридическом давлении расшифровать данные невозможно.
- В случае необходимости мы закрываем сервис в регионе, чем нарушаем приватность.
