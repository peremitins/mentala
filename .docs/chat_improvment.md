````md
# ТЗ: Генерация “чипов продолжения” (Suggested Replies) после каждого ответа ИИ

Версия: 1.1  
Дата: 2026-01-10

## 1) Цель

После каждого сообщения ИИ в чате показывать пользователю до 5 “чипов” — готовых продолжений диалога (варианты того, что пользователь может спросить/сказать дальше).  
Чипы должны:

- звучать “по-человечески”, понятно и естественно,
- быть разнообразными и не повторяться по кругу,
- соответствовать контексту последнего ответа ИИ и всей ветки диалога,
- помогать вести живой разговор (без ощущения сценария).

---

## 2) UX / UI требования

### 2.1 Где и когда показывать

- Чипы отображаются **сразу под последним сообщением ИИ**.
- Чипы генерируются **после формирования финального ответа ИИ** и приходят в том же SSE-стриме (см. раздел 5).
- Чипы исчезают/скрываются:
  - после того, как пользователь нажал на один чип (и он отправился в чат),
  - или когда пользователь начал печатать и отправил свой текст,
  - или после прихода следующего ответа ИИ (старые чипы не показываются).

### 2.2 Количество и длина

- `0…5` чипов (по умолчанию стремимся к 3–5).
- Текст чипа: **до 80 символов** (желательно 25–70), без “канцелярита”.
- Чипы должны быть “смысловыми”, а не «Уточнить детали».

### 2.3 Поведение при клике

- По нажатию чипа — его текст отправляется как сообщение пользователя.

---

## 3) Что генерируем (контент)

### 3.1 Определение чипа

Чип — это **естественная следующая реплика пользователя**, которая логично продолжает разговор.

Чипы должны включать разные типы продолжений:

- уточнение фактов/смысла,
- просьба о примере,
- применение к себе (“как мне понять, что у меня так?”),
- практический шаг (“что сделать сегодня?”),
- альтернативный взгляд/сомнение (“а если наоборот?”),
- мягкая эмоциональная валидизация (“мне тревожно, что делать?”),
- просьба сократить/структурировать (“коротко и по шагам”).

### 3.2 Разнообразие и анти-повторы (обязательно)

Нужно исключить “зацикливание” (одни и те же фразы/структуры).  
Требования:

- В рамках одного набора чипы **не должны быть перефразами одного и того же**.
- Между соседними ответами ИИ нельзя повторять одинаковые чипы.
- На дистанции последних `N=30` чипов (по сессии) повтор допускается **только при низкой семантической похожести** и после попыток регенерации.

## 4) Данные и хранение

Хранение чипов в БД **не требуется**. Чипы генерируются на сервере и передаются вместе с ответом ИИ.

### 4.1 Объект чипа (схема)

Минимальная схема (вариант A):

```json
{
  "text": "Помоги понять, почему вечером тянет на сладкое",
  "intent": "apply_to_self"
}
```
````

`intent` (для аналитики и разнообразия) — одно из:

- `clarify`
- `example`
- `apply_to_self`
- `action_step`
- `reflect`
- `reframe`
- `summarize`
- `support`

---

### 4.2 Zod DTO (обязательно)

- `SuggestedChipDto`: `{ text: string, intent: enum }`.
- `ChatStreamChunkDto`: `{ output_text_delta?: string, chips?: SuggestedChipDto[], error?: { code: string, message: string } }`.
- `ChatResponseDto` (для `/api/chat`): доп. поле `chips?: SuggestedChipDto[]`.
- Фронт валидирует чанк/ответ через Zod и игнорирует некорректные чипы.

---

## 5) Контракт API

### 5.1 Генерация ответа ИИ + чипов (SSE)

`POST /api/chat/stream`

Request:

```json
{
  "messages": [{ "role": "user", "content": "..." }],
  "sessionId": "uuid",
  "therapySessionId": 123,
  "lang": "ru"
}
```

Response (SSE chunks):

```text
data: {"output_text_delta":"..."}
...
data: {"chips":[{"text":"...","intent":"clarify"}]}
data: [DONE]
```

Правила:

- `therapySessionId` **обязателен**. Если тариф/лимит не позволяет — возвращаем ошибку в SSE (`data: {"error": {...}}`).
- Чипы приходят **одним отдельным чанк‑сообщением** в конце стрима (перед `[DONE]`).
- Все новые поля ответа/стрима должны быть описаны в Zod‑DTO (`shared/dto/*`) и валидироваться на фронте.
- Если чипы не пришли (ошибка/пустой ответ), фронт должен спокойно продолжать без них.
- Лимит `maxChips = 5` задаётся сервером (конфигом), параметр с фронта не обязателен.

### 5.2 Синхронный чат (опционально, без стрима)

Если используется `POST /api/chat`, то чипы возвращаются в JSON‑ответе вместе с `message`.

```json
{
  "message": { "role": "assistant", "content": "..." },
  "chips": [{ "text": "...", "intent": "clarify" }]
}
```

### 5.3 SSE‑типизация чанков

Типы событий (в JSON внутри `data:`):

- `{"output_text_delta":"..."}` — потоковая часть ответа ИИ
- `{"chips":[...]}`
- `{"error":{"code":"E_xxx","message":"..."}}`

Коды ошибок — согласно архитектурным правилам (`E_AUTH`, `E_FORBIDDEN`, `E_RATE`, `E_VALIDATION`, `E_UNKNOWN`).

## 6) Алгоритм генерации и анти-циклы (обязательно)

### 6.1 Входные данные для генерации

- Последний ответ ИИ (главный контекст).
- Последние `K=10–20` сообщений диалога.
- Профиль/настройки пользователя (если есть): язык, тональность, уровень “жёсткости”.
- История чипов: последние `N=30` по чату.
- Лимит `maxChips = 5` (серверный конфиг).

### 6.2 Шаги генерации

1. **Классификация** ответа ИИ (внутри промпта): объяснение / совет / поддержка / вопрос / план и т.д.
2. Генерация `3–5` чипов, покрывающих разные `intent`.
3. Пост-фильтрация:

   - удаляем дубликаты по строке,
   - удаляем слишком похожие (см. 6.3),
   - проверяем длину и “человечность”.

4. Если осталось < 3 — **одна регенерация** с указанием “избегай похожих формулировок”.
5. Если всё равно плохо — возвращаем пустой список чипов.

### 6.3 Проверка семантической похожести (рекомендуется)

- Храним эмбеддинги чипов (или делаем быстрый similarity по n-gram + Levenshtein как минимум).
- Порог:

  - внутри одного набора: similarity > 0.82 → считаем повтором
  - с историей последних N: similarity > 0.88 → считаем повтором

- Если повтор — заменяем/регенерируем конкретный чип, а не весь набор (если возможно).

## 7) Промпты (самое важное)

Ниже — набор промптов, рассчитанный на то, чтобы **не уходить в цикл** и выдавать **живые, разные** варианты.

### 7.1 System prompt (для чип-генератора)

> Ты — генератор вариантов реплик пользователя (suggested replies) для продолжения диалога.
> Твоя задача: создать до 5 коротких, естественных, разнообразных чипов на русском языке.
> Чипы должны быть понятными, “человеческими”, без канцелярита и без повторов.
> Избегай шаблонов вроде: “Уточнить детали”, “Расскажи больше”, “Приведи пример” — вместо этого формулируй живые фразы.
> Никогда не повторяй ранее предложенные чипы, если они есть в списке “recent_chips”.
> Не задавай медицинских диагнозов. Не пиши предупреждений и дисклеймеров — только варианты реплик пользователя.

### 7.2 Developer prompt (структура и JSON-вывод)

> Сгенерируй `1..maxChips` чипов.
> Требования:
>
> - Каждый чип — реплика пользователя в первом лице, адресованная ассистенту.
> - Запрещены терапевтические вопросы к собеседнику (например: “Что тебя беспокоит?”).
> - Если контекста недостаточно — дай общие варианты продолжения разговора от лица пользователя.
> - Минимум 2 чипа должны быть короткими (до 40 символов).
> - Разнообразие по `intent`: не меньше 3 разных intent, если maxChips >= 4.
> - Запрещены повторы по смыслу и по формату.
> - Не используй одинаковое начало фразы более чем у 1 чипа.
> - Длина `text` (или `label`) <= 80 символов.
> - Тон: дружелюбный, взрослый, без сюсюканья.
>   Вывод строго в JSON по схеме:

```json
{
  "chips": [
    { "text": "...", "intent": "clarify" },
    { "text": "...", "intent": "apply_to_self" }
  ]
}
```

### 7.3 Runtime prompt (вставляемые данные)

Переменные:

- `assistant_answer`
- `dialog_context` (последние K сообщений)
- `recent_chips` (последние N чипов)
- `primary_topic` (если чат запущен из привычек/терапии)
- `maxChips`

Текст:

> Контекст диалога:
> {{dialog_context}}
>
> Последний ответ ИИ:
> {{assistant_answer}}
>
> Недавние чипы (нельзя повторять по смыслу и формулировке):
> {{recent_chips}}
>
> Основная тема (если есть): {{primary_topic}}
> Если тема указана — минимум один чип должен явно упоминать её.
>
> Сгенерируй до {{maxChips}} чипов.

### 7.4 “Анти-зацикливание” (вторая попытка, если нужно)

Если после фильтрации мало чипов или есть повторы, делаем повторный вызов с добавкой:

> В прошлой попытке были повторы/слишком похожие формулировки.
> Сгенерируй новые чипы, максимально отличающиеся по структуре фраз, глаголам и углу вопроса.
> Запрещено начинать фразы одинаковыми словами. Запрещены общие фразы без смысла.

---

## 8) Правила качества текста (человечность)

Чипы должны:

- звучать как реальный человек (“мне важно понять…”, “можешь помочь…”, “а если…”),
- избегать канцелярита, терминов без нужды,
- быть конкретными (“вечером тянет на сладкое” вместо “как улучшить питание”),
- не быть слишком длинными.

---

## 9) Аналитика (метрики)

Собираем:

- CTR чипов (набор → клик),
- распределение intent,
- процент случаев, когда пользователь игнорирует чипы,
- процент повторов (до фильтра / после фильтра),
- среднюю длину чипов,
- влияние на глубину сессии (сообщений на чат).

---

## 10) Acceptance Criteria (критерии приёмки)

1. После каждого ответа ИИ показывается 0–5 чипов, обычно 3–5.
2. Чипы на русском, понятные, без ошибок, длина <= 80 символов.
3. Внутри одного набора нет смысловых дублей.
4. За последние 30 чипов чата не появляется повтор с similarity > 0.88.
5. При сбое генерации чипы не показываются.
6. Нажатие на чип отправляет его как сообщение пользователя и запускает ответ ИИ.
7. Чипы исчезают после отправки сообщения пользователя.
8. В API используется `POST /api/chat/stream`, чипы приходят отдельным финальным SSE‑чанком перед `[DONE]`.
9. `therapySessionId` обязателен; при отсутствии доступа/лимита возвращается ошибка.
10. Ошибки в стриме соответствуют формату `{ error: { code, message } }`.
11. Все новые поля ответа/стрима покрыты Zod‑DTO.

---

## 11) План внедрения (по шагам)

**Этап 1 (MVP):**

- Генерация чипов одним стрим‑вызовом `/api/chat/stream`.
- 3–5 чипов, без эмбеддингов, только строковые анти-повторы + “recent_chips”.

**Этап 2 (качество):**

- Эмбеддинги и семантический фильтр похожести.
- Intent-баланс и регенерация точечно.
