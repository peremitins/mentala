# Техническое задание: микро-практика «Выгрузка мыслей»

Статус: предварительное, актуализировано 27.02.2026.

## 1. Цель

Добавить в «Быструю помощь» отдельную микро-практику «Выгрузка мыслей», чтобы пользователь мог быстро выгрузить мысли в текстовом или голосовом формате с быстрым стартом через чипы-подсказки.

Ключевые требования:

- Чипы-подсказки обязательны и вставляют текст в поле ввода.
- Голосовой ввод использует тот же нативный механизм диктовки, что и чат.
- Дублирование кода запрещено: переиспользуются существующие компоненты и composables.
- Экран должен выглядеть аккуратно и спокойно, с лёгкими анимациями.
- Лимит текста: **10 000 символов**.

## 2. Точки входа и маршрутизация

### 2.1 Вход из «Быстрой помощи»

На экране `/quick-help` добавить пятую карточку:

- Заголовок: `Выгрузка мыслей`
- Подпись: `Быстро разгрузить голову и выплеснуть эмоции`
- Иконка: `message-square-pen` (из текущего набора иконок)
- Действие: переход на экран практики «Выгрузка мыслей»

### 2.2 Канонический маршрут

Использовать единый маршрут: `/quick-help/thought-dump`.

Вариант `/quick-help/dump` не использовать, чтобы не плодить альтернативные URL.

## 3. UI и UX

Экран состоит из трёх зон: шапка, рабочая область, панель действий.

### 3.1 Шапка

- Заголовок: `Выгрузка мыслей`
- Рядом с заголовком размещается небольшой inline-иконка с вопросительным знаком "?".
- Поведение иконки:
  - На десктопе: при наведении курсора появляется тултип.
  - На мобильных устройствах: при тапе открывается тултип или нижний лист (bottom-sheet).
- Текст тултипа:
  "Практика свободного письма используется в психологии для снижения эмоционального напряжения. Даже короткая запись помогает мозгу структурировать переживания и уменьшить внутренний шум."
- Тултип должен быть коротким, без внешних ссылок, без цитат и без длинного прокручиваемого контента.
- Тултип использовать, который уже используется в проекте.

### 3.1.1 - Описание: `Пиши как есть. Это безопасное пространство.`

### 3.2 Поле ввода

Большое многострочное поле:

- Дефолтный placeholder: `Начни с одной фразы. Например: «Меня тревожит...»`
- При выборе чипа placeholder может меняться в контексте выбранного старта
- Автофокус при открытии экрана включать только там, где это не ломает мобильный UX
- Черновик не сохраняется локально: при выходе со страницы текст автоматически очищается

### 3.3 Чипы-подсказки

Расположение: над полем ввода, чтобы были видны до начала печати.

Набор для MVP:

- `Меня тревожит, что...`
- `Я злюсь, потому что...`
- `Мне страшно, что...`
- `Я устал от...`
- `Я не могу перестать думать о...`
- `Мне сейчас нужно...`
- `Я чувствую...`
- `Самое тяжёлое сейчас...`

Поведение:

- Если поле пустое, чип вставляет фразу целиком.
- Если поле не пустое, фраза добавляется с новой строки.
- После вставки курсор ставится в конец текста.
- Последний выбранный чип можно подсветить (лёгкая анимация нажатия).

### 3.4 Голосовой ввод

Кнопка микрофона размещается рядом с полем ввода или в панели действий.

Требования:

- Использовать существующий нативный механизм диктовки из чата.
- Если текущая реализация зашита в чат, вынести её в общий модуль (`useNativeDictation` или `VoiceDictationButton.vue`) и переиспользовать в обеих точках.
- Результат диктовки вставлять в конец текущего текста (с переносом строки, если поле не пустое).
- Если диктовка недоступна, показывать понятный toast и оставлять рабочий текстовый сценарий.

### 3.5 Панель действий

После ввода доступны действия:

- `Стереть` (очистить поле)
- `В чат` (по явному клику отправить содержимое как контекст и открыть чат)

Требование по приватности: без явного нажатия кнопки `В чат` ничего не отправляется.
После успешной передачи в чат поле ввода очищается.

## 4. Анимации

Минимальный набор:

- Появление экрана: `fade + slight slide`
- Чипы: короткое нажатие (`scale 0.98`) и возврат
- Кнопка `Стереть`: мягкое исчезновение текста + лёгкая вибрация (если хаптика доступна на устройстве)

Анимации должны одинаково корректно работать на Web, iOS и Android.

## 5. Переиспользование и технические ограничения

### 5.1 Переиспользование диктовки

- Единый источник логики диктовки для чата и экрана «Выгрузка мыслей».
- Нельзя копировать существующий код диктовки в новый компонент.

### 5.2 Переиспользование каталога карточек «Быстрой помощи»

- Новая карточка добавляется в общий каталог карточек `quick-help`.
- Хардкод карточки в странице не допускается.

### 5.3 Кроссплатформенные ограничения

- Перед использованием браузерных API проверять доступность через `typeof`.
- Для нативных функций использовать Capacitor-плагины или существующие обёртки проекта.
- Асинхронные операции писать через `async/await` + `try/catch` (без `.then().catch()`).

## 6. Критерии приемки

1. На `/quick-help` отображается карточка `Выгрузка мыслей`.
2. Карточка открывает страницу `/quick-help/thought-dump`.
3. Экран корректно работает на Web, iOS и Android.
4. Поле ввода поддерживает лимит 10 000 символов без ошибок курсора и ввода.
5. Чипы вставляют текст строго по правилам (в пустое поле и с новой строки в непустое).
6. Голосовой ввод работает через тот же механизм, что и в чате, без дублирования реализации.
7. При недоступной диктовке пользователь получает понятный fallback (toast + ручной ввод).
8. Без клика по `В чат` отправка не происходит. После клика открывается чат и сразу запускается запрос ассистенту на основе переданного контекста выгрузки (без предварительного показа текста в textarea чата).
9. Введённый текст не сохраняется локально и очищается при уходе со страницы.
10. После успешного действия `В чат` поле очищается.

## 7. Принятые решения

1. Черновик локально не сохраняется (для конфиденциальности).
2. После передачи текста в чат поле очищается.
