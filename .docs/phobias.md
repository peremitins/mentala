# ТЗ: тема терапии «Страхи»

## 1. Цель

Добавить в каталог терапии отдельную системную тему для работы со страхами, избеганием и повторяющимися пугающими сценариями.

Тема должна быть полезна как для широких пользовательских формулировок уровня «мне страшно», так и для более конкретных запросов уровня «боюсь летать», «боюсь выступать», «боюсь лифтов».

## 2. Принцип формулировок

Во внешнем UX используем язык «страхи» и «то, что пугает», а не клинические диагнозы. Слово «фобия» допустимо:

- в рабочих документах и внутренних ключах;
- в ответе ИИ только если сам пользователь так назвал свою тему.

ИИ не должен самоназначать диагноз формулировками вида «у тебя фобия».

## 3. Параметры темы

| Параметр           | Значение                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| Внутренний ключ    | `phobias`                                                                                         |
| Название           | `Страхи`                                                                                          |
| Краткое описание   | `Помогаем мягко встретиться со страхами и вернуть ощущение контроля: маленькие шаги и поддержка.` |
| Позиция в каталоге | `2`, сразу после `Тревога и паника`                                                               |
| Emoji              | `🛡️`                                                                                              |
| Цвет карточки      | `orange`                                                                                          |

Итоговый порядок системных тем после внедрения:

1. `anxiety` — Тревога и паника
2. `phobias` — Страхи
3. `stress` — Стресс и выгорание
4. `anger` — Раздражительность и злость
5. `selfesteem` — Самооценка и самокритика
6. `relations` — Отношения и границы

Важно: старая версия ТЗ была неконсистентна с актуальным каталогом, потому что не учитывала тему `relations`. В новой версии это исправлено.

## 4. Поведение карточки темы

На экране `/therapy` тема должна отображаться как обычная системная карточка каталога в текущем визуальном паттерне.

Карточка должна содержать:

- название;
- описание;
- emoji;
- быстрые действия.

Для темы `phobias` быстрые действия обязательны:

- `Поговорить`;
- `Медитация`;
- `Дыхание`.

На этапе v1 не нужен отдельный контент-пул медитаций и дыхательных практик именно под фобии. Разрешённый и ожидаемый вариант:

- медитация маппится на существующую тему `anxiety`;
- дыхание маппится на существующую группу `anxiety`.

Это должно быть явно зафиксировано в реализации, а не оставлено как «если предусмотрено».

## 5. Поведение на детальной странице темы

На странице `/therapy/phobias` должны работать те же основные сценарии, что и у остальных системных тем:

- просмотр описания темы;
- вход в чат по кнопке `Поговорить об этом`;
- переход к медитациям;
- переход к дыхательным практикам;
- переход к настройкам уведомлений.

Ключевое отличие темы `phobias`: старт ИИ-чата не должен быть общим и абстрактным. Для этой темы нужен специальный стартовый сценарий выбора конкретного страха.

## 6. Сценарий входа в ИИ-чат

Раздел 6 описывает UX-логику сценария. Источником истины для prompt-логики является раздел 10.

### 6.1. Что считаем стартом сценария

Специальный сценарий включается при welcome-start чата, когда:

- пользователь входит из темы `Страхи`;
- `entryContext.type = "therapy_topic"`;
- `entryContext.topic_id = "phobias"`;
- чат стартует без пользовательских сообщений.

Если пользователь просто возвращается в уже открытый диалог с непустой историей, повторно показывать стартовый сценарий не нужно.

### 6.2. Первый вход или нет сохранённой подтемы

Если у пользователя нет валидного сохранённого фокуса внутри `phobias`, ассистент должен запустить сценарий первичного выбора подтемы.

Текст сообщения не фиксируется. Фиксируется только структура:

- 1 короткая вводная фраза;
- перечисление популярных категорий страхов (`3–5` пунктов максимум);
- 1 уточняющий вопрос в конце.

### 6.3. Повторный вход, если подтема уже обсуждалась

Если у пользователя есть валидный и ещё актуальный `lastPhobiaFocus`, при новом welcome-start ассистент должен сначала предложить выбор:

- продолжить прошлую подтему;
- выбрать другую тему страха.

Текст сообщения не фиксируется. Фиксируется только UX-правило: сначала спросить про продолжение или смену фокуса, и только потом переходить к предметному разговору.

Ассистент может коротко назвать `label` прошлой подтемы, чтобы пользователь понял, о чём именно идёт речь.

Если прошлый фокус не подтверждён или устарел по TTL, этот сценарий не включать.

### 6.4. Если пользователь выбирает другую тему

Если пользователь выбирает `Другая тема`, сценарий должен вернуться к первичному выбору из пункта `6.2`, а не перескакивать сразу к советам.

В следующем сообщении ассистент должен снова показать базовый список категорий и задать один уточняющий вопрос.

## 7. Популярные подтемы страхов

Список категорий для первого шага должен быть фиксированным, чтобы продукт, prompt и UX не расходились между релизами.

Базовые категории:

1. Страх публичных выступлений
2. Страх высоты
3. Страх замкнутых пространств
4. Социальный страх

Правила для перечисления в тексте первого сообщения:

- допустимо раскрывать `социальный страх` через формулировки уровня `люди`, `оценка`, `общение`, `знакомства`;
- `страх публичных выступлений` и `социальный страх` считаются соседними, но разными пользовательскими входами;
- перечисление должно оставаться коротким и не превращаться в длинный каталог.

Если пользователь отвечает своей формулировкой, которая не совпадает со списком, это валидный сценарий. Примеры допустимого «другого» варианта:

- страх общения или знакомств;
- пауки или насекомые;
- собаки или другие животные;
- темнота;
- поездки одному;
- любой другой конкретный страх.

## 8. Suggested chips для стартового шага

Нужно учитывать текущее ограничение `SuggestedChipDto.max(5)`.

Поэтому стартовые chips для первого входа фиксируем так:

1. `Страх публичных выступлений`
2. `Страх высоты`
3. `Страх замкнутых пространств`
4. `Социальный страх`
5. `Другая тема`

Для повторного входа chips фиксируем так:

1. `Продолжить прошлую тему`
2. `Другая тема`

Если пользователь нажал `Другая тема`, ассистент в следующем сообщении показывает базовый список из пункта `7`.

## 9. Правила сохранения контекста

Чтобы сценарий повторного входа был детерминированным, нужно хранить последнюю подтверждённую подтему внутри темы `phobias`.

`subtopicKey` должен быть нормализованным slug-ключом, а не произвольной строкой.

Минимально достаточная структура:

```json
{
  "topicId": "phobias",
  "subtopicKey": "public_speaking",
  "subtopicLabel": "Страх публичных выступлений",
  "confirmedByUser": true,
  "updatedAt": "2026-03-09T12:00:00.000Z"
}
```

Требования к записи:

- сохранять только после явного выбора пользователя;
- выбор через chip считается явным подтверждением;
- текстовый ответ пользователя тоже считается явным подтверждением, если он прямо назвал страх;
- если ассистент только предположил подтему, но пользователь её не подтвердил, ничего не сохранять;
- при смене темы внутри `phobias` сохранять новое значение поверх старого.
- если `updatedAt` старше `30 дней`, сценарий продолжения не показывать;
- устаревший фокус можно хранить в БД, но он не должен влиять на welcome-start, пока пользователь не подтвердит его заново.
- `subtopicKey` должен заполняться только из нормализованного словаря значений. Базовые примеры: `public_speaking`, `heights`, `confined_spaces`, `social_fear`.

Рекомендуемое техническое место хранения: `chat_settings.last_therapy_focus` как `jsonb` или эквивалентная структура того же уровня ответственности.

## 10. Согласованные prompt-правила

Ниже целевой prompt-фрагмент для special-case логики темы `phobias`.

```text
Если entryContext.type = "therapy_topic" и entryContext.topic_id = "phobias":

1. Не захардкоживай конкретный текст сообщения. В продукте фиксируется структура ответа, а не готовая фраза.
2. Не начинай с общего приветствия и не используй шаблон "Чем могу помочь?".
3. Если у пользователя нет валидного lastPhobiaFocus:
   - дай 1 короткую поддерживающую вводную фразу;
   - кратко обозначь, что полезно начать с конкретной ситуации;
   - перечисли популярные категории страхов из раздела 7;
   - закончи 1 уточняющим вопросом.
4. Если у пользователя есть валидный lastPhobiaFocus:
   - сначала предложи выбор: продолжить прошлую тему или выбрать другую;
   - не предполагай, что старая тема всё ещё актуальна;
   - можешь коротко напомнить label прошлой темы;
   - если пользователь выбирает другую тему, вернись к перечислению популярных категорий.
5. Не называй состояние диагнозом без слов пользователя.
6. Не предлагай резкую экспозицию, давление или формат "просто сделай и всё пройдёт".
7. До выбора конкретной подтемы не уходи в длинную психообразовательную лекцию.
8. После выбора подтемы помогай через уточнение триггеров, избегания, мыслей и телесной реакции.
9. Стартовое сообщение должно оставаться коротким: обычно `2–4 предложения`.
```

## 11. Что должно измениться в реализации

Обязательные точки изменения:

- `app/lib/therapyCatalog.ts` — добавить системную тему `phobias` и скорректировать порядок;
- `app/lib/meditations.ts` — добавить маппинг `phobias -> anxiety`;
- `app/lib/practiceActions.ts` — добавить маппинг `phobias -> anxiety`;
- `app/pages/therapy/index.vue` — карточка должна участвовать в списке и quick actions;
- `app/pages/therapy/[key]/index.vue` — кнопка `Поговорить об этом` должна запускать special-case сценарий;
- `server/application/chat/name-greeting.service.ts` — текущая точка для отдельной стартовой логики `topic_id = phobias`; если логика будет расширяться, допустимо вынести её в выделенный entry/welcome-service;
- `server/application/prompts/index.ts` и/или слой server-side prompt assembly — отдельное правило для выбора/продолжения подтемы;
- storage chat context — сохранение и чтение `lastPhobiaFocus`.

## 12. Аналитика

Минимальный набор событий:

- `therapy_topic_open` с `topicKey = phobias`;
- `therapy_quick_chat_click` с `topicKey = phobias`;
- `phobias_selector_shown`;
- `phobias_focus_selected`;
- `phobias_focus_resumed`;
- `phobias_focus_changed`.
- `phobias_session_started` — пользователь выбрал новую или прошлую подтему, и предметный разговор по конкретному страху реально стартовал.

## 13. Критерии готовности

Задача считается выполненной, если:

- тема `Страхи` добавлена в системный каталог терапии;
- тема отображается второй по порядку;
- итоговый каталог содержит 6 системных тем, включая `relations`;
- у карточки доступны `Поговорить`, `Медитация`, `Дыхание`;
- медитация и дыхание для `phobias` ведут в anxiety-группы;
- при первом входе в чат ассистент не использует общий шаблон, а строит сообщение по структуре сценария выбора страхов;
- при повторном входе ассистент сначала спрашивает, продолжать ли прошлую подтему;
- сценарий повторного входа работает только при наличии подтверждённого `lastPhobiaFocus`;
- `lastPhobiaFocus` старше `30 дней` не активирует сценарий продолжения;
- после выбора пользователем конкретной подтемы она сохраняется как последний подтверждённый фокус;
- prompt-логика не использует диагностический и давящий язык;
- аналитика позволяет отделить клик по теме, показ селектора и фактический старт предметного разговора.
