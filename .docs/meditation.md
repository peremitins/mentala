# Техническое задание

## Раздел «Медитации» (MVP v1) — синхронизировано с текущей кодовой базой

Проект: **Mentala**

### 0. Контекст (важно, чтобы не фантазировать)

В текущей кодовой базе:

- **Навигация**: нижняя панель `BottomNav` содержит **4 вкладки**: `Чат / Терапия / Привычки / Настройки`. Добавление новой вкладки = изменение UX/дизайна и сетки.
- **Чат**: “suggested chips” — это DTO `{ text, intent }`, но на клиенте чип **всегда отправляется как текст в чат**, без выполнения навигации/действия.
- **Мультимедиа**: озвучка/аудио сейчас реализованы через `HTMLAudioElement` (см. `useTTS`) + защиту под web/capacitor.
- **Кроссплатформенность**: доступ к `document/window/navigator` должен быть через проверки (`typeof`, `isDocumentAvailable()`), нативные штуки — через Capacitor плагины.

Этот документ описывает MVP так, чтобы его реально можно было сделать в текущей архитектуре (Nuxt 4 + Pinia + Tailwind + shadcn-vue + vue-query + Nitro API).

## 1. Цель и роль функциональности

### 1.1. Назначение

Раздел «Медитации» нужен как “быстрый инструмент самопомощи”:

- **самостоятельное использование** (поставить фон, расслабиться, уснуть, сфокусироваться),
- **поддержка привычки** `meditation` (она уже есть в каталоге привычек),
- **поддержка терапии** (как “инструмент/практика” рядом с темой),
- **контекстная рекомендация ИИ** (в чате).

### 1.2. Цели MVP v1 (равноприоритетно)

- Снижение тревоги/напряжения
- Улучшение засыпания/качества сна
- Повышение фокуса
- Эмоциональная регуляция

## 2. Scope v1 (что делаем)

### 2.1. Форматы контента (только без голоса)

В v1 реализуем **только фоновые аудио-форматы**, без речи/гайда:

- **Soundscapes** (природа): дождь, лес, океан, ночь, огонь…
- **Ambient / музыка без голоса**
- **Таймер медитации**: без аудио или с выбранным фоном (soundscape/ambient).

❌ Guided meditation с голосом — **не входит** в v1.  
🔜 В будущем: ИИ‑голос/гайд.

### 2.2. Объём контента v1

- Аудио-треков: **20–30**
- Длительность:
  - основная: **10–30 минут**
  - допускаются короткие 1–5 минут (как “быстрые паузы”)

### 2.3. Локализация

- v1: **только RU**, без i18n.

## 3. Темы и связность с текущими разделами

### 3.1. Важное несоответствие и как его исправляем

В текущей кодовой базе “темы терапии” ограничены каталогом `THERAPY_TOPICS` и **не содержат** прямых тем “Сон” / “Фокус”. Поэтому в v1 вводим **свои темы медитаций** и делаем **маппинг** на терапию/привычки.

### 3.2. Темы медитаций v1 (внутренние)

Минимальный набор:

- Сон
- Тревога
- Стресс
- Фокус
- Самооценка / самосострадание
- Эмоции (злость/грусть/раздражение)
- Тяга / срыв (под привычки “quit”)

### 3.3. Маппинг на терапию (пример, уточняется)

- Сон → `stress` / `anxiety`
- Тревога → `anxiety`
- Стресс → `stress`
- Самооценка → `selfesteem`
- Эмоции → `mood` / `anger`
- Фокус → `perfectionism` (как “анти‑перфекционизм”) или отдельная тема медитаций без пары
- Тяга/срыв → чаще привязка к привычкам (`smoking`, `alcohol`, `sugar`, …), а не к терапии

## 4. UX и навигация (v1 под текущий UI)

### 4.1. Точки входа (минимум 3)

Чтобы выполнить критерий “3 разных способа”, в v1 делаем:

1. **Из привычек**: из привычки `meditation` (карточка/деталка) → кнопка “Открыть медитации”.
2. **Из терапии**: на странице темы терапии → CTA “Попробовать практику” → подборка медитаций (фильтр по маппингу).
3. **Из чата**: ассистент рекомендует практику и даёт “быстрый переход”.

### 4.2. Вкладка в нижнем меню — как делаем “без боли”

**Решение (принято):** добавляем **5‑ю вкладку** “Медитации” в `BottomNav`.

Последствия для UI:

- нижняя навигация становится **grid-cols-5** (или аналогичная раскладка);
- нужен выбор иконки и подписи (например, `🧘` / Lucide `lotus`, если ок);
- роут вкладки: **`/meditations`** (см. 11.1).

### 4.3. Функции пользователя v1

- Запуск/пауза/стоп трека
- Выбор длительности (если трек “бесконечный” или “loop”)
- Таймер авто‑остановки (10/20/30 минут + “без таймера”)
- Плавный **fade‑in/fade‑out**
- **Избранное** (MVP: синхронизация на сервере; хранение по пользователю)

## 5. Данные и хранение (MVP)

### 5.1. Формат аудио

- MP3 (основной)

### 5.2. Где лежат аудио и как стримим (нужно выбрать)

**Решение (принято):**

- MP3 файлы лежат в **`public/meditations/*`** (стримим как статический контент).
- Каталог треков — **в таблице БД** (источник истины по метаданным/группировкам).
- Это **осознанное упрощение для v1** (вместо R2 + подписанных URL).

Как это совместить:

- В БД храним `audioPath` вида `/meditations/<slug>.mp3` (или полный URL, если нужно).
- Фронт строит URL как `${PUBLIC_APP_ORIGIN}${audioPath}` (или просто относительный путь на web).

Важно (ограничение выбранной стратегии):

- MP3 в `public/` = **обновление аудиофайлов требует релиза/деплоя** фронта.
- Таблица в БД в этом варианте даёт: сортировку/фичефлаги/переименования/теги/подборки **без релиза**, но не “загрузку нового аудио”.

Оффлайн/предзагрузка: **не делаем** в v1.

### 5.3. Метаданные лицензий (не показываем пользователю)

Минимально:

```ts
{
  source: string;
  license: "CC0" | "Pixabay" | "FreePD";
  originalUrl?: string;
}
```

### 5.4. Обложки треков

- Хранение: **`public/meditations/covers/*`**.
- В БД: `coverPath` вида `/meditations/covers/<slug>.webp` (или полный URL).
- Показываются в каталоге и на экране трека.

### 5.5. API v1 (минимум)

Каталог:

- `GET /api/meditations` → список треков, фильтрация по теме (`?topic=<key>`).
- `GET /api/meditations/topics` → список тем (ключ + имя RU).

Избранное (синхронизация между устройствами):

- `GET /api/meditations/favorites` → список избранных треков.
- `POST /api/meditations/favorites` → добавить в избранное (`{ trackId }`, idempotent).
- `DELETE /api/meditations/favorites/:trackId` → убрать из избранного.

Требования:

- DTO через Zod в `shared/dto/*`, валидация на фронте и бэке.
- Ошибки в формате `{ error: { code, message } }`.
- Поля каталога v1 — минимально необходимые (без доп. атрибутов вроде bpm/mood).

## 6. Плеер (кроссплатформенный)

### 6.1. Базовые требования

- Плеер работает на **Web + iOS 13+ + Android 8+**
- Автоплей не гарантирован (iOS/Safari): старт воспроизведения только после **явного действия пользователя**
- Fade‑in/fade‑out реализуется изменением громкости по таймеру (с проверкой доступности API)
- Таймер авто‑остановки должен корректно работать при сворачивании/возврате (расчёт по `Date.now()`, а не только по `setInterval`)
 - Один трек воспроизводится одновременно по всему приложению (singleton‑подход, как в `useTTS`)

### 6.2. Поведение таймера

- Пользователь выбирает: `10/20/30` минут или `без таймера`
- При срабатывании таймера: делаем **fade‑out**, затем стоп, UI показывает “Сессия завершена”
 - Стандартные фейды: **fade‑in 1.5s**, **fade‑out 2.5s**

### 6.3. Фоновое воспроизведение как в Calm (принято)

**Решение (принято):** пользователь задаёт дефолтную длительность таймера в настройках (или выключает таймер).  
Если выбрано, например, “30 минут”, то:

- при сворачивании приложения аудио **продолжает играть** оставшееся время;
- таймер считается по “реальному времени” (`Date.now()`), чтобы не ломаться при background.

Техническое уточнение (нужно учитывать в реализации):

- на iOS фоновое аудио требует корректной настройки (capabilities/аудио‑сессии). Это не всегда “само получится” на одном `HTMLAudioElement` внутри WebView.
 - Для треков допускается **loop**, но в каталоге могут быть и треки без loop (если не удалось найти подходящие).

## 7. Интеграция с ИИ‑чатом (реалистично под текущие DTO)

### 7.1. Что есть сейчас

Сейчас “chips” в чате — это подсказки‑кнопки, которые **просто отправляют текст в чат**, они **не умеют** открывать экран медитаций.

### 7.2. Варианты для MVP (нужно выбрать)

- **Вариант A (быстро)**: ассистент пишет текстом “Откройте раздел Медитации → …”, а пользователь переходит сам (через CTA в терапии/привычках/настройках).
- **Вариант B (правильно, но требует изменений)**: расширяем чипы до “action chips”, чтобы ассистент мог вернуть кнопку типа “Открыть медитацию X” и клиент сделал `navigateTo('/meditations?track=...')`.

**Решение (принято):** выбираем **Вариант B** (action‑chips / deep link).

### 7.2.1. Контракт action‑chips (минимум для v1)

Текущий контракт чипов: `{ text, intent }` и на фронте чип отправляется как текст в чат.  
Для медитаций нужно добавить “чип‑действие”, который **не отправляет текст**, а выполняет навигацию.

Минимальные действия:

- открыть `/meditations`
- открыть конкретный трек
- открыть подборку (по теме)

Предлагаемый формат (v1):

- `kind: "text" | "action"` (по умолчанию `"text"` для обратной совместимости)
- для `kind="action"`:
  - `action: "open_meditations" | "open_meditation_track" | "open_meditations_collection"`
  - `params`:
    - `trackId?: string` (для конкретного трека)
    - `collectionId?: string` (для подборки)

Требования к обратной совместимости:

- если клиент не знает `kind="action"`, он должен безопасно игнорировать такие чипы;
- сервер в переходный период может отдавать и текстовую подсказку параллельно (fallback).

### 7.2.2. Требования к серверной генерации

- ИИ может генерировать action‑chips только из разрешённого набора `action/*`
- Сервер валидирует ответ по Zod‑DTO (невалидные action‑chips отбрасываем, а не ломаем чат)
- В тексте ответа ассистент всё равно даёт 1–2 предложения “зачем” (см. 7.3)

### 7.2.3. Требования к фронту

- UI чипов остаётся единым (как кнопки), но обработчик клика:
  - если `kind="text"` → отправляем в чат как сейчас
  - если `kind="action"` → выполняем `navigateTo(...)` и (опционально) показываем тост/микро‑подпись “Открываю медитации…”

### 7.3. Объяснение при рекомендации

Ассистент при рекомендации даёт 1–2 предложения “зачем”, без медицинских утверждений.

Пример:

> «Этот фон помогает снизить напряжение и чуть легче перейти ко сну. Давайте включим на 20 минут?»

## 10. Критерии готовности (DoD)

Фича готова, если:

- пользователь может **зайти и запустить** медитацию минимум **3 разными способами** (см. 4.1),
- аудио стабильно играет/останавливается на web/iOS/Android,
- fade‑in/fade‑out и таймер работают предсказуемо,
- нет лицензионных рисков (источник и тип лицензии зафиксированы),
- интеграция с ИИ‑чатом выбрана (вариант A или B) и реализована согласно выбранному,
- есть каталог медитаций с фильтром по темам и синхронизированными избранными.
