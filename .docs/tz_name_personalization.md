# ТЗ: Удаление имени из уведомлений + приветствие по имени в чате 1 раз в день

Дата: 2026-02-06

## 1. Контекст и ссылки

Обязательные документы:

- @.docs/mentai_tz_product.md
- @.docs/arch_rules.md
- @.docs/mentai_tz_frontend.md
- @.docs/mentai_tz_backend.md
- @.docs/security_requirements.md
- @.docs/architecture.md (обновить при внедрении)

## 2. Цель

- Убрать упоминание имени пользователя из всех уведомлений (шаблоны, AI‑тексты, UI подсказки).
- В чате ограничить приветствия **до 1 раза в день** (локальная дата пользователя).
- Персональное приветствие по имени — **только** в начале сессии и **не чаще 1 раза в день**.

## 3. Не в скоупе

- Изменение визуального UI/дизайна экранов (кроме точечных текстов).
- Рефакторинг логики уведомлений, не связанный с именем.
- Переработка онбординга (кроме использования имени в приветствии).

## 4. Текущее состояние (по коду)

Ниже места, где имя используется или может использоваться:

Уведомления и шаблоны:

- `app/lib/notificationTemplates.ts` — почти все тексты содержат плейсхолдер `{name}`.
- `shared/utils/notificationText.ts` — подставляет имя в `{name}` и чистит пунктуацию.
- `server/application/notifications/text-selection.service.ts` — форматирует тексты через `formatNotificationTextWithName`.
- `server/application/notifications/ai-generation.service.ts` — в промпте разрешает `{name}` и выводит “Имя пользователя”.
- `app/components/notifications/NotificationTextsEditorPage.vue` — подсказка: “Можно использовать {name}...”.

Чат/промпты:

- `server/application/prompts/index.ts` — контекст пользователя (имя/пол) и welcome‑промпты.
- `server/infrastructure/llm/openai.ts` — формирует welcome‑старт и использует `buildWelcomePrompt`.
- `server/api/chat/stream.post.ts`, `server/interface/api/chat.post.ts` — передают `user_name` в LLM‑опции.

Профиль:

- `server/infrastructure/db/schema.ts` — `users.name`, `users.timezone`.

## 5. Требования: уведомления без имени

### 5.1. Шаблоны уведомлений

- Удалить `{name}` из всех шаблонов в `app/lib/notificationTemplates.ts`.
- Переписать формулировки так, чтобы они звучали корректно без имени.
- Сохранить текущий тон и адресность (на «ты/вы»).

### 5.2. AI‑генерация уведомлений

- В `server/application/notifications/ai-generation.service.ts` убрать инструкции про `{name}`.
- Запретить использование имени пользователя в AI‑текстах (явно прописать в промпте).
- Удалить строку “Имя пользователя: …” из контекста или заменить на “Имя пользователя не использовать”.

### 5.3. Форматирование и совместимость

- В `shared/utils/notificationText.ts` заменить `formatNotificationTextWithName` на функцию, которая:
  - удаляет `{name}` при наличии (на случай старых пользовательских текстов),
  - корректирует пунктуацию/пробелы,
  - сохраняет логику родовых вариантов (скобки) при необходимости.
- `server/application/notifications/text-selection.service.ts` использовать новую функцию без `userName`.

### 5.4. UI для редактирования уведомлений

- В `app/components/notifications/NotificationTextsEditorPage.vue` удалить подсказку про `{name}`

### 5.5. Данные пользователя

- Хранение имени пользователя **не трогаем** (оно нужно для чата и профиля).

## 6. Требования: приветствие по имени в чате

### 6.1. Когда используется приветствие

- Полноценное приветствие (с или без имени) используется **не чаще 1 раза в день**.
- Во все остальные сессии дня — старт без приветствия, с альтернативной стартовой фразой.

- Приветствие по имени происходит **только** в первом сообщении ассистента в начале сессии (welcome‑старт).
- В один календарный день (по локальной тайм‑зоне пользователя) приветствие по имени должно быть **не более 1 раза**, независимо от числа сессий.

### 6.2. Определение имени для приветствия

Нужно вычислять `greeting_name` (отдельно от `user_name`):

- Если имя состоит из нескольких слов — брать **только имя**, а не фамилию.
  - Пример: “Перемитин Николай” → “Николай”.
- Если имя содержит явный никнейм или бессмысленный набор символов — **не использовать** имя.
- Если валидного имени нет — приветствие без имени.

Рекомендуемая эвристика валидного имени:

- допускаются только буквы (латиница/кириллица), дефис и пробелы;
- длина 2–32 символа;
- отсутствие цифр, эмодзи, подчёркиваний, спецсимволов;
- стоп‑слова (например `user`, `test`, `admin`, `guest`, `anon`) → не использовать;
- если после чистки остаётся пусто → не использовать.

Важно: эвристика должна быть **консервативной** — сомневаемся → не используем имя.

### 6.3. Ежедневный лимит приветствий

- Нужен серверный источник истины, чтобы не зависеть от клиента.
- Предложение: добавить поля `chat_settings.last_greeting_at` и `chat_settings.last_name_greeting_at` (timestamp with timezone).
- Логика:
  - Получить текущую дату в тайм‑зоне пользователя (использовать `users.timezone`, fallback `Europe/Moscow`).
  - Если `last_greeting_at` в той же локальной дате → приветствие не использовать, вместо него выдать альтернативный старт.
  - Если `last_name_greeting_at` в той же локальной дате → имя не использовать.
  - Если дата другая → разрешить приветствие и/или приветствие по имени и обновить соответствующие поля.

### 6.4. Промпт

- В `server/application/prompts/index.ts` добавить явное правило для welcome‑промпта:
  - Если `greeting_name` передан, первое предложение приветствия должно содержать это имя.
  - Использовать **только имя**, без фамилии.
  - Если имени нет или оно невалидное — приветствие нейтральное.
- Инструкцию/промпт про валидацию имени добавлять **только** в первое сообщение дня (в тот же момент, когда решаем использовать имя). Во все остальные запросы это правило не включать, чтобы не раздувать токены.
- Если приветствие уже было сегодня — добавить инструкцию начать сообщение с альтернативной стартовой фразы и **не использовать** слова приветствия.
- В `server/infrastructure/llm/openai.ts` использовать `greeting_name` при формировании welcome‑промпта.

## 7. Критерии приёмки

- В уведомлениях не встречается имя пользователя (шаблонные и AI‑тексты).
- `{name}` отсутствует в дефолтных шаблонах и UI‑подсказках.
- Старые пользовательские тексты с `{name}` отображаются без артефактов пунктуации.
- В чате приветствие по имени:
  - есть в первой сессии дня при валидном имени,
  - отсутствует во второй и последующих сессиях того же дня,
  - отсутствует всегда при невалидном имени.
- В чате приветствие (любое) используется только в первой сессии дня; далее — альтернативные стартовые фразы без приветствия.

## 8. План тестирования

- Unit‑тест на `extractGreetingName()`:
  - “Перемитин Николай” → “Николай”.
  - “Nikolaev Nikolai” → “Nikolai”.
  - “xX*D4rk*” → null.
- Интеграция чата:
  - 2 сессии в один день → имя только в первой.
  - 2+ сессии в один день → приветствие только в первой, далее альтернативные старты.
  - сессия в следующий день → имя снова.
- Уведомления:
  - шаблонные тексты без `{name}` и без лишних запятых.
  - AI‑тексты не содержат имени.

## 9. Риски и крайние случаи

- Пользователь меняет имя в течение дня → приветствие остаётся единоразовым.
- Неизвестный/пустой timezone → используем fallback и фиксируем в логах.
- Параллельные старты сессий → возможна гонка, нужно атомарно обновлять `last_name_greeting_at`.
