# ТЗ: Восстановление пароля через email-ссылку

## 1. Обзор

Реализация стандартного flow восстановления пароля через "магическую ссылку" в email. Это самый популярный и понятный для пользователей способ восстановления пароля.

**КРИТИЧНО:** Все функции должны работать на всех платформах:

- **Web** (браузеры)
- **iOS** (через Capacitor)
- **Android** (через Capacitor)

## 2. Текущее состояние

### 2.1. Проблемы

1. **На экране входа (`/auth`):**

   - Кнопка "Забыли пароль?" ведёт на `/forgot`, но страницы не существует

   - Пользователи не могут восстановить забытый пароль

   - Нет страницы смены пароля по токену

   - Нет email-шаблона для ссылки восстановления

### 3.2. Backend API

#### 3.2.1. `POST /api/auth/password/forgot`

**Назначение:** Запрос на восстановление пароля. Отправляет email со ссылкой.

**Request:**

```typescript
{
  email: string; // required, валидируется как email
}
```

**Response (успех):**

```typescript
{
  message: string; // "Если аккаунт существует, мы отправили ссылку на email"
  maskedEmail?: string; // маскированный email для показа пользователю (например: "u***@g***.com")
}
```

**Response (rate limit):**

```typescript
{
  message: string; // "Слишком много запросов"
  retryAfter?: number; // секунды до следующей попытки
}
```

**Логика:**

1. Нормализовать email
2. Проверить rate limit:
   - По IP: максимум 5 запросов в час
   - По email: максимум 3 запроса в час
   - По комбинации IP+email: максимум 5 запросов в час (дополнительная защита от abuse)
   - Ключи: `auth:rate_limit:password_reset:ip:{ip}`, `auth:rate_limit:password_reset:email:{email}`, `auth:rate_limit:password_reset:ip_email:{ip}:{email}`
3. Проверить, существует ли пользователь с таким email и есть ли у него пароль:
   - Если пользователя нет или пароля нет → всё равно вернуть успех (защита от enumeration)
   - Если пользователь есть и пароль есть → продолжить
4. Сгенерировать токен восстановления:
   - Использовать `randomBytes(32).toString('hex')` (64 символа)
   - Вычислить хэш токена: `tokenHash = sha256(token + secret)` (где `secret` из `AUTH_EMAIL_CODE_SECRET` или отдельный `AUTH_PASSWORD_RESET_SECRET`)
   - Хранить в Redis: `auth:password_reset:{tokenHash}` (НЕ сырой токен!)
   - Значение: `{ email: string, createdAt: ISO string }`
   - TTL: 1 час (3600 секунд)
5. Отправить email со ссылкой:
   - URL: `${appUrl}/reset-password?token=${token}` (сырой токен в URL, но в Redis хранится только хэш)
   - `appUrl` из `NUXT_PUBLIC_APP_URL` (критично: использовать публичную переменную, не `NUXT_PRIVATE_API_BASE`)
6. Логировать security event: `password_reset_requested` (без PII, только IP и userAgent)
7. Вернуть успешный ответ (всегда одинаковый, независимо от существования пользователя)

**Защита от enumeration:**

- Всегда возвращать одинаковое сообщение
- Не раскрывать, существует ли пользователь
- Отправлять email только если пользователь существует и имеет пароль

**Rate limiting:**

- При превышении лимита возвращать `retryAfter` в секундах
- Устанавливать заголовок `Retry-After` в ответе

#### 3.2.2. `POST /api/auth/password/reset`

**Назначение:** Смена пароля по токену из email.

**Request:**

```typescript
{
  token: string; // required, токен из query параметра URL (передаётся в body запроса)
  password: string; // required, minlength=8
  confirmPassword: string; // required, должен совпадать с password
}
```

**Важно:** `token` передаётся в **body** запроса (POST), а не в query параметрах. Токен берётся из query параметра URL страницы `/reset-password?token=...` и передаётся в body при отправке формы.

**Response (успех):**

```typescript
{
  success: true;
  user: {
    id: number;
    email: string;
    name: string;
    // ... другие поля пользователя
  };
  sessionToken?: string; // только для native платформ
}
```

**Логика:**

1. Валидировать body (пароли совпадают, длина >= 8)
2. Вычислить хэш входящего токена: `tokenHash = sha256(token + secret)`
3. Получить данные из Redis: `auth:password_reset:{tokenHash}` (искать по хэшу, не по сырому токену)
4. Если токен не найден или истёк:
   - Логировать security event: `password_reset_token_invalid` (без PII)
   - Вернуть ошибку: "Ссылка недействительна или истекла" (400) — одинаковое сообщение для всех случаев
5. Нормализовать email из токена
6. Найти пользователя по email:
   - Если не найден → ошибка "Ссылка недействительна или истекла" (400) — унифицированное сообщение
   - Если найден, но нет пароля → ошибка "Ссылка недействительна или истекла" (400) — унифицированное сообщение
7. Хешировать новый пароль через `argon2` (тип `argon2id`)
8. Обновить `passwordHash` в БД
9. Удалить токен из Redis (одноразовый)
10. Инвалидировать все сессии пользователя (через `revokeAllUserSessions`)
11. Создать новую сессию (через `createSession`)
12. Логировать security event: `password_reset_success` (без PII, только userId, IP, userAgent)
13. Определить платформу через заголовок `x-platform`
14. Вернуть данные пользователя и sessionToken (только для native платформ: iOS/Android)

**Безопасность:**

- Токен одноразовый (удаляется после использования)
- Токен имеет TTL (1 час)
- Все сессии инвалидируются при смене пароля
- Пароль хешируется через argon2

#### 3.2.3. `GET /api/auth/password/reset/validate?token=...`

**Назначение:** Проверка валидности токена перед показом формы смены пароля.

**Response (успех):**

```typescript
{
  valid: true;
  maskedEmail: string; // маскированный email с бэка (например: "u***@g***.com")
}
```

**Response (ошибка):**

```typescript
{
  valid: false;
  reason: 'invalid'; // всегда 'invalid' (не различаем expired/invalid без доп. данных)
}
```

**Логика:**

1. Получить токен из query
2. Вычислить хэш токена: `tokenHash = sha256(token + secret)`
3. Проверить в Redis: `auth:password_reset:{tokenHash}`
4. Если валиден:
   - Извлечь email из данных
   - Замаскировать email на бэке (функция `maskEmail()`)
   - Вернуть `valid: true` и `maskedEmail` (фронт не делает маскировку)
5. Если невалиден → вернуть `valid: false` и `reason: 'invalid'` (унифицированное сообщение, не различаем expired/invalid)

**Функция маскировки email:**

```typescript
function maskEmail(email: string): string {
  const [localPart, domain] = email.split('@');
  if (!localPart || !domain) return '***@***';

  const maskedLocal = localPart.length > 1 ? `${localPart[0]}***` : '***';

  const [domainName, ...domainParts] = domain.split('.');
  const maskedDomain =
    domainName && domainName.length > 1 ? `${domainName[0]}***` : '***';

  const tld = domainParts.length > 0 ? domainParts.join('.') : '';
  return `${maskedLocal}@${maskedDomain}${tld ? '.' + tld : ''}`;
}

// Примеры:
// "user@example.com" → "u***@e***.com"
// "test@gmail.com" → "t***@g***.com"
// "a@b.co" → "a***@b***.co"
```

**Использование:**

- На фронте при загрузке `/reset-password?token=...` проверить валидность
- Если невалиден → показать ошибку и предложить запросить новую ссылку

### 3.4. Redis структура

**КРИТИЧНО:** В Redis хранится хэш токена, а не сырой токен!

**Ключ:** `auth:password_reset:{tokenHash}` (где `tokenHash = sha256(token + secret)`)

**Значение (JSON):**

```json
{
  "email": "user@example.com",
  "createdAt": "2024-01-01T12:00:00.000Z"
}
```

**TTL:** 3600 секунд (1 час)

**Примечание:**

- Токен одноразовый (удаляется после использования)
- После успешной смены пароля токен удаляется из Redis
- **Безопасность:** Если Redis утечёт, злоумышленник не получит рабочие ссылки (только хэши)
- Secret для хэширования: `AUTH_PASSWORD_RESET_SECRET` или `AUTH_EMAIL_CODE_SECRET` (если отдельный не задан)

### 3.5. Rate limiting

**По IP:**

- Ключ: `auth:rate_limit:password_reset:ip:{ip}`
- Лимит: 5 запросов в час
- Окно: 3600 секунд

**По email:**

- Ключ: `auth:rate_limit:password_reset:email:{email}`
- Лимит: 3 запроса в час
- Окно: 3600 секунд

**По комбинации IP+email (рекомендуется):**

- Ключ: `auth:rate_limit:password_reset:ip_email:{ip}:{email}`
- Лимит: 5 запросов в час
- Окно: 3600 секунд
- **Назначение:** Резко снижает abuse на одном адресе (например, один IP пытается восстановить пароли для множества email)

**При превышении:**

- Возвращать `retryAfter` в секундах
- Устанавливать заголовок `Retry-After` в ответе

### 3.6. Безопасность

#### 3.6.1. Защита от enumeration

- Всегда возвращать одинаковое сообщение на `/api/auth/password/forgot`
- Не раскрывать, существует ли пользователь
- Отправлять email только если пользователь существует и имеет пароль

#### 3.6.2. Защита токена

- Токен генерируется криптографически стойким способом (`randomBytes(32)`)
- Токен одноразовый (удаляется после использования)
- TTL: 1 час
- Хранится в Redis (не в БД)

#### 3.6.3. Инвалидация сессий

- При смене пароля все существующие сессии пользователя инвалидируются
- Создаётся новая сессия после успешной смены пароля

#### 3.6.4. Логирование

Логировать security events в таблицу `security_events`:

- **`password_reset_requested`**: при успешном запросе на восстановление (без PII, только IP, userAgent)
- **`password_reset_success`**: при успешной смене пароля (userId, IP, userAgent, без пароля)
- **`password_reset_token_invalid`**: при попытке использовать невалидный/истёкший токен (без PII, только IP, userAgent, reason)

**Формат логирования:**

```typescript
await db.insert(securityEvents).values({
  userId: userId || null, // null для запросов, userId для успешных смен
  eventType:
    'password_reset_requested' |
    'password_reset_success' |
    'password_reset_token_invalid',
  ipAddress: ip,
  userAgent: userAgent,
  metadata: {
    /* без чувствительных данных */
  },
});
```

### 3.7. Кроссплатформенность

#### 3.7.1. Web

- Ссылка открывается в браузере
- После смены пароля → автоматический вход → редирект на главную
- Сессия создаётся через httpOnly cookie

#### 3.7.2. iOS/Android (Capacitor)

- Ссылка открывается в приложении (deep link или universal link)
- После смены пароля → автоматический вход
- Сессия создаётся через `sessionToken` в ответе (для native)

**Deep link:**

- **Web URL:** `https://mentala.app/reset-password?token=...` (основная ссылка в email)
- **Deep link URL:** `mentala://reset-password?token=...` (опционально, для прямого открытия в приложении)
- **Universal link:** `https://mentala.app/reset-password?token=...` (iOS автоматически откроет приложение, если настроено)

**Обработка:**

- В email отправляется web-ссылка (работает везде)
- На web-странице `/reset-password` показать кнопку "Открыть в приложении" (если доступен deep link)
- При открытии ссылки в приложении → показать экран смены пароля
- После успешной смены → сохранить `sessionToken` в localStorage и войти

## 7. Тестирование

### 7.1. Сценарии

1. **Успешное восстановление:**

   - Запрос ссылки → получение email → открытие ссылки → смена пароля → вход

2. **Несуществующий email:**

   - Запрос ссылки → получение успешного ответа (без раскрытия существования)

3. **Истёкший токен:**

   - Попытка использовать токен после 1 часа → ошибка

4. **Использованный токен:**

   - Использование токена дважды → ошибка при второй попытке

5. **Rate limiting:**

   - Множественные запросы → блокировка → таймер

6. **Валидация пароля:**

   - Несовпадение паролей → ошибка
   - Короткий пароль → ошибка

7. **Инвалидация сессий:**
   - Вход с нескольких устройств → смена пароля → все сессии инвалидированы

## 9. Примечания

### 9.1. Безопасность

- **Токен:** генерируется через `randomBytes(32)` (64 hex символа)
- **Хранение:** в Redis хранится хэш токена (`sha256(token + secret)`), а не сырой токен
- **Secret:** используется `AUTH_PASSWORD_RESET_SECRET` или `AUTH_EMAIL_CODE_SECRET` (если отдельный не задан)
- **TTL токена:** 1 час (можно настроить через env, но 1 час — стандарт)
- **Rate limit:** 5 запросов в час с IP, 3 с email, 5 с IP+email (можно настроить)
- **Пароль:** хешируется через `argon2` (тип `argon2id`)
- **Сессии:** все сессии инвалидируются при смене пароля (безопасность)

### 9.2. Конфигурация

**Переменные окружения:**

- **`NUXT_PUBLIC_APP_URL`:** публичная переменная для URL приложения (использовать в reset-ссылках)
  - Пример: `https://mentala.app` или `http://localhost:3000` (для dev)
  - **Критично:** использовать именно `NUXT_PUBLIC_APP_URL`, а не `NUXT_PRIVATE_API_BASE`
  - **Обновить `nuxt.config.ts`:** в `runtimeConfig.public.appUrl` заменить `process.env.NUXT_PRIVATE_API_BASE` на `process.env.NUXT_PUBLIC_APP_URL` (или добавить fallback: `process.env.NUXT_PUBLIC_APP_URL || process.env.NUXT_PRIVATE_API_BASE || 'http://localhost:3000'`)
- **`AUTH_PASSWORD_RESET_SECRET`:** секрет для хэширования токенов (опционально, можно использовать `AUTH_EMAIL_CODE_SECRET`)

**CSRF middleware:**

- Новые эндпоинты должны быть исключены из CSRF проверки в `server/middleware/csrf.ts`:
  - `/api/auth/password/forgot` (POST)
  - `/api/auth/password/reset` (POST)
  - **Примечание:** `/api/auth/password/reset/validate` (GET) не нужно добавлять, так как CSRF проверка не применяется к GET-запросам

### 9.3. Кроссплатформенность

- **Web:** сессия через httpOnly cookie
- **iOS/Android:** сессия через `sessionToken` в ответе (сохраняется в localStorage)
- **Deep links:** опционально, основная ссылка — web URL (работает везде)
