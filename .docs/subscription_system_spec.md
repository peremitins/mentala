# Mentala — система подписок и биллинга

Версия: 1.0  
Дата: 2025-12-12

---

## 1. Общее описание

**Mentala** — кроссплатформенное приложение для психологической поддержки и работы с привычками:

- AI-терапия (чат + сценарии);
- уведомления и трекеры привычек.

Нужна единая система подписок, работающая на:

- **Web** (основное место оплаты и управления),
- **iOS и Android** (отображение статуса и инструкций; интерфейс одинаковый для обеих платформ).

**Оплата и изменение тарифа происходят только через веб-версию** (сайт Mentala, интеграция с YooKassa).  
В мобильных приложениях (iOS и Android) отображается:

- текущий тариф и срок,
- сравнение тарифов,
- инструкция, как перейти на сайт и оплатить/изменить подписку.

---

## 2. Цели системы

1. Ввести три тарифа: `Basic`, `PRO`, `Premium`.
2. Реализовать **пробный период (Trial)** как временное состояние тарифа Basic с полным доступом Premium на 7 дней.
4. Использовать **YooKassa** как основной платёжный агрегатор для РФ.
5. Поддержать **годовые планы** со скидкой ~20% от суммы 12 месяцев.
6. Сделать UX максимально прозрачным и дружелюбным.
7. Заложить модели и события для дальнейшей аналитики (реализация аналитики — позже).
8. **Обеспечить единый интерфейс для iOS и Android** — визуальное оформление и структура экранов должны быть идентичными на обеих мобильных платформах.

## 3. Тарифная модель

### 3.1. Базовые тарифы

| Тариф       | Цена (месяц)    | Годовой план (ориентир) | Функциональность                                 | Лимиты времени             |
| ----------- | --------------- | ----------------------- | ------------------------------------------------ | -------------------------- |
| **Basic**   | 0 ₽ (бесплатно) | —                       | Только уведомления с шаблонами (без ИИ)          | 0 минут в неделю           |
| **PRO**     | 349 ₽ / мес     | ~20% скидка на год      | AI-чат, уведомления, трекер привычек             | 100 минут в неделю         |
| **Premium** | 649 ₽ / мес     | ~20% скидка на год      | Всё из PRO + расширенная аналитика и уведомления | 100 минут в неделю         |

**Пробный период (Trial)**:

- **Trial — это не отдельный тариф, а временное состояние тарифа Basic.**
- При регистрации автоматически создаётся подписка `planId = 'basic'` с флагом `trialActive = true`.
- Trial длится 7 дней (`trialEndedAt = now + 7 days`).
- Во время Trial (`trialActive = true`) пользователь получает **полный функционал Premium**:
  - AI-чат с ИИ
  - Уведомления и трекер привычек
  - Лимит времени: **100 минут в неделю** (как у Premium)
- После окончания Trial (`trialEndedAt < now`):
  - `trialActive` становится `false` (вычисляется автоматически)
  - Пользователь остаётся на тарифе Basic
  - Доступ к ИИ блокируется, остаются только уведомления с шаблонами
  - Лимит времени: **0 минут в неделю**
- Повторный Trial невозможен: `hasUsedTrial = true` устанавливается при активации и больше никогда не сбрасывается.

**Важно:** Разница между PRO и Premium не в количестве минут (оба дают 100 минут в неделю), а в функциональности:

- **PRO**: AI-чат, уведомления, трекер привычек.
- **Premium**: всё из PRO + расширенная аналитика и уведомления.

### 3.2. Годовые планы

Для PRO и Premium:

- годовой план = `месячная цена * 12 * 0.8` (скидка ~20%);
- в интерфейсе показывать обе цены:  
  _«349 ₽ в месяц или 3 350 ₽ в год (−20%)»_ (для PRO),  
  _«649 ₽ в месяц или 6 230 ₽ в год (−20%)»_ (для Premium).

**Примечание:** Basic тариф всегда имеет `billingPeriod = 'month'`, так как цена 0 и это технический placeholder.

     > Осталось 37 мин на этой неделе

   - Анимация: без тяжёлых эффектов, только аккуратный ре-рендер числа при смене значения (лёгкий fade). Никакого "моргающего красным" и скачущего текста.

   - Прогресс-бар + цифры "X / 100 минут"

### 4.2. Общая логика

Везде есть единый экран **«Подписка»** (Subscription):

- **Web** — полноценное управление (выбор и оплата).
- **iOS и Android** — тот же экран по структуре и визуальному оформлению, но:

  - нет кнопок оплаты/смены плана;
  - вместо них — блок с **подробной инструкцией**, как открыть сайт и оформить/изменить подписку.

> **Текущий план:** Premium
> Действует до: 12 февраля 2026
>
> **Использовано:** 63 из 100 минут на этой неделе
> Лимит обновится в понедельник.
>
> [ Управлять подпиской ]

- оформление:

  - карточка с тем же стилем, что остальные элементы (тёмный фон, лёгкая обводка);
  - текст белый/серый, кнопка-пилюля в фирменном цвете (фиолетовый Mentala);
  - справа можно поставить иконку 💳 или значок короны для Premium.

По нажатию на «Управлять подпиской»:

- в **web-версии** — переход на страницу `/subscription`;
- в **мобильных приложениях (iOS и Android)** — переход на экран `SubscriptionScreen` внутри приложения (родной экран, не webview; интерфейс одинаковый для обеих платформ).

## 5. Особенности UX по платформам

### 5.1. Web

**Функционал:**

- выбор тарифа;
- переключение «месяц/год»;
- старт процесса оплаты;
- отображение результата (успех/ошибка);
- отмена автопродления и смена тарифа (через отдельные кнопки / ссылки).

**Флоу оплаты (web):**

1. Пользователь выбирает тариф.
2. Нажимает `Оформить подписку`.
3. Frontend вызывает backend (`POST /api/subscriptions/start-checkout`) и получает `payment_url` YooKassa.
4. Пользователь переходит на страницу YooKassa, вводит данные.
5. YooKassa шлёт webhook на бекенд (`POST /api/payments/yookassa/webhook`) → бекенд активирует подписку (`UserSubscription`).
6. **Возврат пользователя после оплаты:**

   - YooKassa поддерживает `return_url` в параметрах платежа — URL, на который пользователь вернётся после оплаты.
   - Frontend должен настроить `return_url = https://mentala.app/subscription?payment_id={payment_id}`.
   - При возврате пользователя frontend проверяет статус подписки через `GET /api/subscriptions/current`.
   - Если оплата успешна — показывается экран успеха:
     > 🎉 Подписка оформлена
     > Ваш план: Premium, действует до 12 февраля 2026.
   - Если оплата не завершена — показывается соответствующее сообщение с возможностью повторить оплату.

   **Примечание:** Детали реализации возврата пользователя и обработки webhook'ов YooKassa уточняются при изучении официальной документации YooKassa API.

### 5.2. Мобильные приложения (iOS и Android)

**Нет прямой оплаты в приложении.**
Оплата и смена тарифа только через веб.

**Интерфейс одинаковый для iOS и Android.**

Экран «Подписка» на мобильных:

1. Блок **«Текущий план»** (как в вебе).
2. Блок карточек тарифов (для понимания, _что_ он получит).
3. Блок **инструкции**:

Пример текста:

> #### Как оформить или изменить подписку
>
> 1. Откройте браузер и перейдите на **mentala.app**.
> 2. Войдите в свой аккаунт.
> 3. Откройте раздел **«Подписка»** в настройках.
> 4. Выберите тариф и оплатите удобным способом.
>
> После оплаты вернитесь в приложение — доступ откроется автоматически.

4. Кнопка:

- `Открыть сайт mentala.app`
  — открывает системный браузер по URL `https://mentala.app/subscription` (или корень + авто-редирект после авторизации).

Если надо минимизировать риски с Apple/Google, кнопку можно сделать опциональной (через фичу-флаг), оставив только текст-инструкцию.

## 7. Backend — модели и API

### 7.1. Модель `SubscriptionPlan`

```ts
type PlanName = 'basic' | 'pro' | 'premium';

interface SubscriptionPlan {
  id: string; // 'basic', 'pro', 'premium'
  name: PlanName;
  basePrice: number; // базовая месячная цена (рубли) для фикс-планов (для Basic = 0)
  weeklyMinutesLimit: number; // лимит минут в неделю (для Basic = 0, для PRO/Premium = 100)
  isVisibleInUI: boolean; // можно скрывать тестовые планы
}
```

Хранится в конфиге (таблица/файл). Цена рассчитывается на основе `basePrice` и периода оплаты (`billingPeriod`).

**Важно:** Trial — это не отдельный план, а временное состояние Basic. План `'trial'` не существует в таблице `subscription_plans`.

### 7.2. Модель `UserSubscription`

```ts
type PaymentStatus = 'active' | 'expired' | 'pending' | 'canceled';

interface UserSubscription {
  id: string;
  userId: string;
  planId: string;
  billingPeriod: 'month' | 'year'; // период оплаты
  startDate: Date;
  endDate: Date;
  paymentStatus: PaymentStatus;
  autoRenew: boolean;
  createdAt: Date;
  updatedAt: Date;
  // для аналитики
  sourcePlatform: 'web' | 'ios' | 'android';
}
```

**Модель `User` (дополнение):**

```ts
interface User {
  // ... другие поля
  hasUsedTrial: boolean; // по умолчанию false, устанавливается в true при активации Trial
  trialStartedAt?: Date; // дата начала Trial (для аналитики)
  trialEndedAt?: Date; // дата окончания Trial (для аналитики)
  billingCredit: number; // внутренний кредит в рублях, по умолчанию 0 (для возвратов при смене плана)
  timezone: string; // IANA timezone для расчета недель
}

// Вычисление активного Trial (не хранится в БД)
function isTrialActive(user: User): boolean {
  if (!user.trialEndedAt) return false;
  return new Date(user.trialEndedAt) > new Date();
}
```

**Важно:**

- `trialActive` не хранится как отдельное поле в БД, а вычисляется по `trialEndedAt > now()`.
- Trial может быть активен только если `planId = 'basic'`.
- После апгрейда на платный тариф: `trialEndedAt = now()`, `hasUsedTrial = true` (Trial становится "израсходованным" моментально).

### 7.3. Основные эндпоинты

Все пути примерные, подстроить под реальную архитектуру (Nuxt server / Nest / др.).

#### GET `/api/subscriptions/plans`

- **Назначение:** получить список доступных тарифов.
- **Ответ:** массив `SubscriptionPlan` (только видимые в UI).

#### GET `/api/subscriptions/current`

- **Назначение:** получить текущую подписку пользователя с информацией о Trial и доступных функциях.
- **Ответ:**

```json
{
  "plan": "basic",
  "trialActive": true,
  "trialExpiresAt": "2025-01-20T00:00:00Z",
  "features": {
    "ai": true,
    "weeklyMinutesLimit": 100
  },
  "subscription": {
    "id": 1,
    "planId": "basic",
    "billingPeriod": "month",
    "startDate": "2025-01-13T00:00:00Z",
    "endDate": "2025-02-13T00:00:00Z",
    "paymentStatus": "active",
    "plan": {
      "id": "basic",
      "name": "basic",
      "basePrice": 0,
      "weeklyMinutesLimit": 0
    }
  },
  "user": {
    "billingCredit": 0,
    "hasUsedTrial": true,
    "timezone": "Europe/Moscow"
  },
  "noActiveSubscription": false
}
```

**Логика:**

- `trialActive` вычисляется по `user.trialEndedAt > now()`.
- `features.ai` = `true` если `trialActive || planId in ['pro', 'premium']`.
- `features.weeklyMinutesLimit` = `100` если `trialActive`, иначе из плана.

#### POST `/api/subscriptions/start-checkout` (web)

- **Тело:**

```json
{
  "planId": "premium",
  "billingPeriod": "month"
}
```

- **Логика:**

  - Валидирует параметры плана.
  - Если это смена плана — вычисляет доплату/возврат по алгоритму из раздела 8.3.
  - Создаёт запись `UserSubscription` со статусом `pending`.
  - Создаёт платёж в YooKassa через их API:
    - Использует метод создания платежа из YooKassa API (детали уточняются при изучении документации).
    - Передаёт `return_url` для возврата пользователя после оплаты.
    - Передаёт `metadata` с `userId` и `subscriptionId` для обработки webhook'а.
  - Возвращает `payment_url` и `subscriptionId`.

- **Ответ:**

```json
{
  "paymentUrl": "https://yookassa.ru/pay/...",
  "subscriptionId": "...",
  "amount": 649,
  "toPay": 250 // если это смена плана, показывает доплату
}
```

**Примечание:** Детали интеграции с YooKassa API (методы создания платежа, обработка webhook'ов, автопродление) уточняются при изучении официальной документации YooKassa.

#### POST `/api/payments/yookassa/webhook`

- принимает вебхук от YooKassa;
- по `subscriptionId` или `metadata.userId` находит запись;
- при успешной оплате:

  - ставит `paymentStatus = 'active'`;
  - устанавливает `startDate`, `endDate`;
  - `autoRenew = true` (если оформлена подписка) или false (если разовый платёж);

- при отказе/отмене:

  - `paymentStatus = 'canceled'` или оставить `pending` и логировать ошибку.

#### POST `/api/subscriptions/cancel`

- для веб-подписок:

  - **Автопродление:**
    - YooKassa поддерживает автопродление подписок (recurring payments).
    - При отмене подписки backend должен отключить автопродление через YooKassa API (детали уточняются при изучении документации).
    - Ставит `autoRenew = false` в БД.
  - Подписка остаётся активной до `endDate` — пользователь сохраняет доступ до конца оплаченного периода.
  - После `endDate` подписка автоматически переходит в статус `expired`.

**Примечание:** Детали работы с автопродлением в YooKassa (создание подписки с автопродлением, управление статусом) уточняются при изучении официальной документации YooKassa API.

_В мобильных приложениях (iOS и Android) этот эндпоинт напрямую не используется (отмена — через сайт)._

## 8. Бизнес-логика

### 8.1. Активация Trial

- При создании нового пользователя:

  - Проверяется флаг `user.hasUsedTrial`:

    - Если `hasUsedTrial === false` → активируем Trial, ставим `hasUsedTrial = true`.
    - Если `hasUsedTrial === true` → Trial не активируется, создаётся Basic без Trial.

  - При активации Trial создаётся `UserSubscription`:

    - `planId = 'basic'` (не 'trial'!)
    - `startDate = now`
    - `endDate = now + 30 days` (или другой период для Basic, технически)
    - `paymentStatus = 'active'`
    - `autoRenew = false`
    - `billingPeriod = 'month'`

  - Обновляется `User`:

    - `trialStartedAt = now`
    - `trialEndedAt = now + 7 days`
    - `hasUsedTrial = true`
    - `timezone = timezone || 'Europe/Moscow'` (дефолтный timezone)

- **Правила:**

  - `trialActive === true` возможно только если `planId === 'basic'`.
  - `hasUsedTrial === true` означает, что Trial больше никогда не станет активным для этого пользователя.
  - При апгрейде на платный тариф: `trialEndedAt = now()`, Trial становится "израсходованным" моментально.

- **Защита от повторной регистрации:**

  - На уровне БД: email и/или телефон должны быть уникальными.
  - Если человек регистрируется с тем же email/телефоном:
    - либо связываем с существующим аккаунтом (восстановление доступа),
    - либо не даём создать новый аккаунт.
  - IP/устройство/фингерпринты — можно заложить на будущее, но для MVP достаточно:
    - `hasUsedTrial` + уникальный контакт (email/phone).

### 8.2. Истечение Trial

- **Проверка при каждом запросе (lazy evaluation):**

  - `trialActive` вычисляется по `user.trialEndedAt > now()`.
  - Если `trialEndedAt < now()` и `planId === 'basic'`:
    - Пользователь остаётся на Basic, но `trialActive = false`.
    - Доступ к ИИ блокируется, остаются только уведомления с шаблонами.
    - Лимит времени: 0 минут в неделю.

- **Опционально (для аналитики):**

  - Крон-задача раз в день может логировать событие `trial_ended` для пользователей, у которых Trial только что истёк.

- При входе пользователя с истёкшим Trial:

  - backend в ответе возвращает `trialActive: false`, `plan: 'basic'`;
  - frontend показывает экран «Пробный период завершён» и предлагает выбрать тариф.

### 8.3. Оформление платной подписки (web)

- Пользователь выбирает тариф на странице `/subscription`.
- Frontend вызывает `start-checkout`.
- После успешной оплаты (вебхук):

  - если был Trial (`planId === 'basic' && trialActive === true`):
    - `trialEndedAt = now()` (Trial становится "израсходованным").
    - Старая подписка Basic переводится в `expired` или `canceled`.
    - Создаётся новая подписка с выбранным `planId` (pro/premium).
  - устанавливается новый `planId`, `startDate`, `endDate`, `paymentStatus='active'`, `autoRenew=true`.

- Если пользователь меняет план (upgrade/downgrade):

  **Важно: пользователь не должен терять деньги при смене плана.**

  Алгоритм пересчета:

  1. Вычисляем оставшиеся дни текущей подписки:
     - `remainingDays = (endDate - now) / (24 * 60 * 60 * 1000)`
     - `totalDays = (endDate - startDate) / (24 * 60 * 60 * 1000)`
     - `usedDays = totalDays - remainingDays`
  2. Вычисляем стоимость использованных дней старого плана:
     - `oldPlanDailyPrice = oldPlanTotalPrice / totalDays`
     - `usedAmount = oldPlanDailyPrice * usedDays`
  3. Вычисляем стоимость оставшихся дней нового плана:
     - `newPlanDailyPrice = newPlanTotalPrice / 30` (или для годовых / 365)
     - `remainingCost = newPlanDailyPrice * remainingDays`
  4. Вычисляем разницу:
     - `difference = remainingCost - (oldPlanTotalPrice - usedAmount)`
     - Если `difference > 0` — пользователь доплачивает разницу (через YooKassa).
     - Если `difference < 0` — разница **не возвращается на карту**, а зачисляется как внутренний кредит (`billingCredit`) и автоматически уменьшает сумму следующих платежей. Денежные возвраты на карту в MVP не делаются.
  5. Применяем новый план:
     - Старая подписка переводится в `expired`.
     - Создается новая подписка с:
       - `startDate = now`
       - `endDate = now + remainingDays` (или продлевается на полный период, если доплата за полный период)
       - `paymentStatus = 'active'` (после успешной оплаты разницы, если требуется)

  **Пример:**

  - Пользователь заплатил PRO (349 ₽) на месяц (30 дней).
  - Использовал 5 дней, осталось 25 дней.
  - Переходит на Premium (649 ₽).
  - Расчет:
    - Использовано: 349 / 30 × 5 = 58.17 ₽
    - Осталось от PRO: 349 - 58.17 = 290.83 ₽
    - Стоимость 25 дней Premium: 649 / 30 × 25 = 540.83 ₽
    - Доплата: 540.83 - 290.83 = 250 ₽

  **Примечание:** Для годовых планов расчет аналогичный, но с учетом 365 дней.

  **Важно: смена тарифа и лимит минут в неделю**

  При смене тарифа в течение недели:

  - `usedMinutesThisWeek` **не сбрасывается** — остаётся как есть.
  - `weeklyMinutesLimit` **переопределяется** значением из нового тарифа сразу.

  **Примеры:**

  - **PRO → Premium** посреди недели:

    - Лимит был 100 → останется 100, ничего не меняется.

  **Логика блокировки даунгрейда:**

  ```ts
  if (newPlan.weeklyMinutesLimit < currentUsedMinutes) {
    throw new DowngradeBlockedError(
      `Нельзя перейти на тариф с меньшим лимитом. Вы уже использовали ${currentUsedMinutes} минут из ${currentPlan.weeklyMinutesLimit}. Лимит нового тарифа: ${newPlan.weeklyMinutesLimit} минут. Попробуйте после понедельника, когда лимит обновится.`
    );
  }
  ```

  **Флоу блокировки:**

  1. Пользователь на `/subscription` выбирает тариф с меньшим лимитом (например, с Premium 100 → Basic 0).
  2. Жмёт "Перейти на Basic".
  3. Frontend вызывает backend: `POST /api/subscriptions/start-checkout`.
  4. Backend проверяет условие и выбрасывает ошибку `DowngradeBlockedError`.
  5. Frontend ловит ошибку и показывает модалку:

  ```
  Сейчас нельзя перейти на этот тариф

  Вы уже использовали 140 минут на этой неделе.
  Лимит тарифа Basic — 0 минут.

  Попробуйте после понедельника, когда лимит обновится.
  ```

  **Для MVP:** Достаточно блокировки в момент попытки + хорошее объясняющее сообщение. Предупреждение "заранее" (серый/заблокированный тариф) можно сделать в будущем.

  **Для MVP:** Достаточно блокировки в момент попытки + хорошее объясняющее сообщение. Предупреждение "заранее" (серый/заблокированный тариф) можно сделать в будущем.

  **Внутренний кредит (billingCredit):**

  Если при смене плана получается переплата (`difference < 0`):

  - Сумма переплаты зачисляется как внутренний кредит в поле `user.billingCredit` (в рублях).
  - Этот кредит автоматически уменьшает следующий платёж:
    - Если новый платёж на 649 ₽, а кредит 200 ₽ → к оплате уйдёт 449 ₽, кредит станет 0.
    - Если кредит больше суммы — платёж может стать 0, остаток кредита останется.
  - Пользователь может видеть меньшую сумму к оплате (или отдельно показывать "учтён бонусный баланс X ₽" для прозрачности).

### 8.4. Лимиты использования (минуты в неделю)

**Важно:** В системе нет понятия "количество сессий" — учитывается только общее количество минут, потраченных в неделю.

#### 8.4.1. Границы недели

- **Неделя = понедельник 00:00 — воскресенье 23:59:59** (по локальному времени пользователя).
- Каждому пользователю при регистрации задаётся `userTimezone` (по умолчанию — из устройства, можно переопределить в настройках).
- Лимит обновляется каждый понедельник в 00:00 по времени пользователя.

#### 8.4.2. Лимиты по тарифам

- **Basic без Trial**: `weeklyMinutesLimit = 0` минут в неделю (только уведомления с шаблонами)
- **Basic с Trial** (`trialActive = true`): `weeklyMinutesLimit = 100` минут в неделю (как у Premium)
- **PRO**: `weeklyMinutesLimit = 100` минут в неделю
- **Premium**: `weeklyMinutesLimit = 100` минут в неделю

#### 8.4.3. Пропорциональный расчет при регистрации

Если пользователь зарегистрировался не в понедельник, ему даётся пропорциональный остаток от недельного лимита.

**Алгоритм:**

```ts
const WEEKLY_LIMIT = subscription.weeklyMinutesLimit; // обычно 100

// d = количество оставшихся дней включая сегодня до конца недели (Пн–Вс)
const today = new Date(); // по времени пользователя
const endOfWeek = getEndOfWeek(today); // воскресенье 23:59:59
const remainingDays = getDaysUntil(today, endOfWeek, inclusive: true); // 1..7

// Пропорциональный расчет
const rawQuota = WEEKLY_LIMIT * remainingDays / 7;

// Округляем до 10 минут для красоты
const initialQuota = Math.floor(rawQuota / 10) * 10;
```

**Примеры:**

- Зарегистрировался в **пятницу** (пт, сб, вс → 3 дня):

  - `rawQuota = 100 * 3 / 7 ≈ 42.8`
  - `initialQuota = floor(4.28) * 10 = 40` минут до конца недели

- Зарегистрировался в **субботу** (2 дня):

  - `rawQuota ≈ 28.5`
  - `initialQuota = 20` минут

- Зарегистрировался в **воскресенье** (1 день):

  - `rawQuota ≈ 14.2`
  - `initialQuota = 10` минут

- Зарегистрировался в **понедельник**:
  - `initialQuota = 100` минут (полный лимит)

В ближайший понедельник 00:00 по времени пользователя выставляется полноценный лимит (`weeklyMinutesLimit`).

#### 8.4.4. Овердрафт (+10 минут сверх лимита)

Для удобства пользователей предусмотрен овердрафт:

- **Номинальный лимит**: `weeklyMinutesLimit` (обычно 100 минут)
- **Овердрафт**: дополнительные 10 минут сверх лимита
- **Максимум**: `weeklyMinutesLimit + 10` минут в неделю

**Поведение:**

```ts
const WEEKLY_LIMIT = subscription.weeklyMinutesLimit; // 100
const WEEKLY_OVERDRAFT = 10;
const usedMinutesThisWeek = getUsedMinutesThisWeek(userId);

if (usedMinutesThisWeek >= WEEKLY_LIMIT + WEEKLY_OVERDRAFT) {
  // Жёстко блокируем — лимит полностью исчерпан
  throw new LimitExceededError(
    'Лимит на эту неделю исчерпан. Обновится в понедельник.'
  );
} else if (usedMinutesThisWeek >= WEEKLY_LIMIT) {
  // Уже в овердрафте — запускаем сессию, но предупреждаем
  showWarning(
    'Вы уже использовали свои 100 минут на этой неделе. Эта сессия — сверх лимита (до 10 минут). В понедельник лимит обновится.'
  );
}
```

**UI-сообщение при переходе в овердрафт:**

> Вы уже использовали свои 100 минут на этой неделе.  
> Мы дадим вам доработать ещё немного (до 10 минут сверх лимита).  
> В понедельник лимит обновится.

#### 8.4.5. Схема хранения использования

**Таблица `therapy_sessions`:**

```ts
interface TherapySession {
  id: string;
  userId: string;
  startedAt: Date; // когда отправлено первое сообщение
  endedAt: Date; // когда сессия завершена
  durationSeconds: number; // длительность в секундах
  // НЕТ поля type — на цену не влияет
}
```

**Функция `getUsageForCurrentWeek(userId)` возвращает:**

```ts
{
  usedMinutes: number; // использовано минут в текущей неделе
  weeklyLimit: number; // лимит минут в неделю из подписки
  overdraftUsed: number; // сколько минут использовано в овердрафте (0-10)
  availableMinutes: number; // доступно минут (с учетом овердрафта)
}
```

#### 8.4.6. Обновление лимита по понедельникам

Крон-задача (каждый понедельник в 00:00 по времени каждого пользователя):

```ts
for (const user of activeUsers) {
  const userTimezone = user.timezone;
  const now = getCurrentTimeInTimezone(userTimezone);

  if (isMonday(now) && now.hour === 0 && now.minute === 0) {
    // Сбрасываем счетчик использованных минут
    user.usedMinutesThisWeek = 0;
    user.overdraftUsed = 0;
    user.availableMinutesThisWeek = user.subscription.weeklyMinutesLimit;
  }
}
```

**Важно: неиспользованные минуты не переносятся**

Неиспользованные минуты **не переносятся** на следующие недели или месяцы. Каждый понедельник лимит минут в неделю обновляется заново в соответствии с тарифом. Подписка даёт доступ к сервису в течение периода, а не накапливаемый "банк минут".

**Пример:**

- Пользователь использовал только 30 минут из 100 на этой неделе.
- В понедельник лимит обновится до 100 минут, неиспользованные 70 минут не сохранятся.
- Это стандартная модель подписки: доступ к сервису в течение периода, а не накопление ресурсов.

Реализацию лимитов можно сделать позже, но интерфейс и модель должны это позволять.

### 8.5. Подсчет времени сессий

**Важно:** Все таймауты синхронизированы и используют единую переменную `CHAT_IDLE_TIMEOUT_MS` из `server/config/subscription.ts` (2 минуты по умолчанию).

#### 8.5.1. Когда начинается сессия

**Сессия начинается в момент, когда пользователь отправил первое сообщение** на экране терапии.

- ❌ Не при открытии экрана терапии
- ✅ **Именно по факту отправки сообщения** (текст или голос — не важно)

**Технически:**

```ts
// Пользователь открыл экран терапии — сессия НЕ началась
onTherapyScreenOpen() {
  // Ждем первого сообщения
}

// Пользователь отправил первое сообщение — сессия началась
onFirstMessageSent(userId, message) {
  const session = {
    userId,
    startedAt: new Date(),
    endedAt: null,
    durationSeconds: 0
  };
  await createTherapySession(session);
}
```

#### 8.5.2. Когда заканчивается сессия

Сессия завершается, когда выполняется одно из условий:

1. **Пользователь явно завершил сессию:**

   - Нажал кнопку "Завершить сессию" (если есть в UI)

2. **Пользователь ушёл с экрана:**

   - Сменился роут (перешёл на другой экран)
   - Закрыл приложение/вкладку

3. **Idle-timeout (неактивность):**

   - Нет ни одного сообщения от пользователя и ни одного ответа от ассистента дольше заданного времени
   - **Таймаут для чата: 2 минуты** (120 секунд)
   - Значение задаётся в конфиге как константа:

     ```ts
     // В server/config/subscription.ts
     export const CHAT_IDLE_TIMEOUT_MS = 2 * 60 * 1000; // 2 минуты в миллисекундах
     ```

   - При таймауте сессия автоматически завершается
   - С возможностью изменить позже без изменения логики (через конфиг)

**При завершении:**

```ts
onSessionEnd(sessionId) {
  const session = await getTherapySession(sessionId);
  const endedAt = new Date();
  const durationSeconds = Math.floor((endedAt - session.startedAt) / 1000);

  // Ограничиваем максимальную длительность активной сессии таймаутом
  // Это предотвращает накопление времени при зависших сессиях
  const maxAllowedSeconds = CHAT_IDLE_TIMEOUT_SECONDS;
  const actualDurationSeconds = Math.min(durationSeconds, maxAllowedSeconds);

  await updateTherapySession(sessionId, {
    endedAt,
    durationSeconds: actualDurationSeconds
  });

  // Списываем минуты (см. ниже)
  await deductMinutesFromWeeklyLimit(session.userId, actualDurationSeconds);
}
```

**Таймаут чата:**

- При таймауте чата завершается therapy сессия

#### 8.5.3. Перевод секунд в минуты для списания

**Правила округления:**

- Если `durationSeconds < 60` → **не списываем ничего** (0 минут)
- Если `durationSeconds >= 60` → округляем **вниз** до целых минут

**Формула:**

```ts
function calculateSessionMinutes(durationSeconds: number): number {
  if (durationSeconds < 60) {
    return 0; // Не списываем, если меньше минуты
  }
  return Math.floor(durationSeconds / 60); // Округляем вниз
}
```

**Примеры:**

- `0:45` (45 секунд) → `0` минут (не списываем)
- `1:01` (61 секунда) → `floor(61/60) = 1` минута
- `9:59` (599 секунд) → `9` минут
- `50:20` (3020 секунд) → `50` минут
- `100:30` (6030 секунд) → `100` минут

**Важно:** Округление вниз защищает пользователя от "пересписания" — если сессия длилась 1 минуту 59 секунд, списывается только 1 минута.

#### 8.5.4. Списание минут

После завершения сессии:

```ts
const sessionMinutes = calculateSessionMinutes(durationSeconds);
await addUsedMinutesToWeek(userId, sessionMinutes);
```

- `subscription_plan_changed` (from → to)
- `subscription_screen_opened` (web/mobile, где mobile включает iOS и Android с одинаковым интерфейсом)

Минимум — сохранять в лог/таблицу `subscription_events` с:

- `userId`

- `metadata` (JSON)

## 10. Acceptance Criteria (сжатый список)

1. Пользователь автоматически получает Basic с Trial (`trialActive = true`) на 7 дней с функционалом Premium.
2. После истечения Trial пользователь остаётся на Basic (`trialActive = false`), доступ к ИИ блокируется, показывается экран выбора тарифа.
3. В Настройках → Общие есть блок «Подписка» с текущим планом и кнопкой «Управлять подпиской».
4. Экран «Подписка» доступен на web/iOS/Android:

   - web: полный функционал выбора/оплаты/смены;
   - мобильные приложения (iOS и Android): статус + тарифы + понятная инструкция и кнопка открытия сайта (интерфейс одинаковый для обеих платформ).

5. Оплата через YooKassa:

   - создаётся платёж;
   - при успехе подписка становится активной;
   - при ошибке/отмене пользователь видит адекватное сообщение.

7. Годовые планы отображаются, цена со скидкой считается корректно.
8. Backend хранит `SubscriptionPlan` и `UserSubscription` по описанным моделям.
9. Все тексты в интерфейсе приведены к дружелюбному тону, нет заглушек.
9. Основные сценарии (Basic с Trial → PRO / Premium → отмена → Basic) проходят без ошибок.

11. Ошибки, крайние случаи и защитные сценарии

### 11.1. Ошибки оплаты

#### Ошибка при создании платежа (до перехода в YooKassa)

- Backend возвращает ошибку (`400 / 500`).
- Frontend:
  - показывает уведомление:
    > Не удалось начать оплату. Попробуйте позже или напишите в поддержку.
  - кнопка «Попробовать снова».

#### Ошибка / отказ оплаты в YooKassa

- YooKassa присылает webhook `payment.canceled` / `payment.failed`.
- Backend:
  - помечает подписку как `paymentStatus = 'canceled'`;
  - сохраняет причину отказа в логах.
- Frontend (при возврате пользователя):
  - показывает экран:
    > Платёж не был завершён  
    > Деньги не списаны. Вы можете попробовать ещё раз или выбрать другой способ оплаты.

### 11.2. Пользователь закрыл страницу оплаты

- Если пользователь:
  - ушёл со страницы YooKassa;
  - закрыл вкладку;
- Подписка остаётся в статусе `pending`.
- Backend:
  - через 30–60 минут кроном переводит `pending` → `canceled`.
- Frontend:
  - при следующем заходе на `/subscription`:
    > Похоже, вы не завершили оплату. Хотите попробовать ещё раз?

## 13. Безопасность и защита от злоупотреблений

### 13.1. Trial

- Один Trial на пользователя (через `hasUsedTrial`).
- Trial — это временное состояние Basic, а не отдельный тариф.
- Проверки:
  - `userId`;
  - `hasUsedTrial` (если `true`, Trial не активируется);
  - email / phone (уникальность);
  - device fingerprint (опционально, позже).
- При попытке повторной регистрации:
  - Trial не активируется (`hasUsedTrial = true`);
  - создаётся Basic без Trial;
  - сразу показывается экран выбора тарифа.

### 13.2. Защита от рассинхронизации

- **Единственный источник правды — backend**.
- Frontend:
  - никогда не рассчитывает доступы сам;
  - всегда запрашивает `/api/subscriptions/current`.

## 14. Интеграция с доступами и функционалом Mentala

### 14.1. Проверка доступа

Перед:

- стартом сессии терапии;
- генерацией уведомлений;

Backend проверяет через централизованный сервис `access.service.ts`:

```ts
// Проверка доступа к ИИ (async функция)
export async function hasAIAccess(
  user: User,
  subscription: UserSubscription | null
): Promise<boolean> {
  const trialActive = isTrialActive(user);
  if (trialActive) return true;
  if (!subscription) return false;
  return ['pro', 'premium'].includes(subscription.planId);
}

// Получение лимита минут (async функция)
export async function getWeeklyMinutesLimit(
  user: User,
  subscription: UserSubscription | null,
  plan?: SubscriptionPlan | null
): Promise<number> {
  if (!subscription) return 0;

  const trialActive = isTrialActive(user);

  // Basic с Trial = 100 минут (как Premium)
  if (subscription.planId === 'basic' && trialActive) {
    return 100;
  }

  // Basic без Trial = 0 минут
  if (subscription.planId === 'basic' && !trialActive) {
    return 0;
  }

  // PRO, Premium = из плана
  return plan?.weeklyMinutesLimit || 100;
}
```

Frontend:

- перехватывает ошибку;
- открывает экран «Подписка».

### 14.2. Поведение по тарифам

| Функция        | Basic (без Trial)   | Basic (с Trial) | PRO | Premium |
| -------------- | ------------------- | --------------- | --- | ------- |
| AI-чат         | ❌                  | ✅              | ✅  | ✅      |
| Уведомления    | ✅ (только шаблоны) | ✅              | ✅  | ✅      |
| Трекер привычек | ✅ (базовый)        | ✅              | ✅  | ✅      |
| Минут в неделю | 0                   | 100             | 100 | 100     |

**Важно:**

- Basic с Trial (`trialActive = true`) = Premium по функционалу.
- Basic без Trial (`trialActive = false`) = только уведомления с шаблонами, без ИИ.
