## MentAI — Детальный план реализации (MVP → MVP+)

### Контекст и цели

- **Цель MVP (2–3 мес)**: Онбординг, чат с ИИ (RU/EN) + TTS/STT, базовый 3D‑аватар, терапия и привычки со статистикой, SOS‑экран, профиль/приватность, биллинг (web Stripe), рефералы. Производительность P95 < 200 ms на BFF, LCP < 2.5s.
- **Основание**: требования из `.docs/MENTAI_TZ_PRODUCT.md`, `.docs/MENTAI_TZ_FRONTEND.md`, `.docs/MENTAI_TZ_BACKEND.md`, правила из `.docs/ARCH_RULES.md`.
- **Принципы**: безопасность по умолчанию, типобезопасность end‑to‑end (Zod DTO), обратимая архитектура (Clean/Hex), fail‑soft UX, a11y.

### Артефакты и документация

- Поддерживаем в актуальном состоянии: `.docs/architecture.md` (диаграммы/модули), `.docs/ARCH_RULES.md` (не меняем без отдельного PR), `.docs/MENTAI_TZ_*` (источник правды требований).
- Любое изменение контрактов — сначала обновляем `shared/dto/*` (см. ARCH_RULES §13), затем сервер, потом фронт.

## Этапы реализации (MVP)

### Этап 0 — Подготовка инфраструктуры (1 неделя)

- Инструменты качества: ESLint + Prettier (+ prettier‑plugin‑tailwindcss), Vitest, Husky + lint‑staged, commitlint + cz‑git.
- Инструменты наблюдаемости: Sentry (client + server), pino логирование на сервере, `X-Request-Id` middleware.
- CI: lint + typecheck + unit‑tests + build (GitHub Actions/GitLab CI). Кэш зависимостей.
- Базовые плагины: `app/plugins/*` (i18n, vue-query.client, sentry.client, icons.client, radix-shadcn).
- Обновление `README.md` и начальное наполнение `.docs/architecture.md` (контур).
- DoD: линт/формат on commit, `npm run test` зелёный, сторимоно‑структура заведена, Sentry ключи из `.env` не закоммичены.

### Этап 1 — Архитектурный каркас и каркас экранов (1 неделя)

- Макеты страниц (пустые заглушки со стейтами loading/empty/error): `index.vue`, `onboarding.vue`, `chat.vue`, `therapy.vue`, `habits.vue`, `sos.vue`, `profile/*`, `billing.vue`.
- Layouts: `default`, `blank`, `auth`. Навигация: нижняя панель, fullscreen‑режим чата.
- Магазины Pinia: `ui`, `user`, `chat` (минимальные состояния, без логики).
- Общие DTO (Zod) заготовки в `shared/dto/*` + базовые константы/утилиты.
- Сервер Nitro: каркас Clean/Hex (`server/{config,domain,ports,application,infrastructure,interface}`), middleware CORS/Helmet/rate‑limit.
- DoD: страницы рендерятся, стейты есть, навигация стабильна, структура серверной части соответствует ТЗ.

### Этап 2 — Аутентификация, профиль, приватность (1 неделя)

- Сервер: `/api/auth/{register,login,refresh,logout}`; JWT (access/refresh) + ротация; `GET /api/user/me`, `PATCH /api/user/update`, `GET /api/user/export`, `POST /api/user/delete`.
- Фронт: формы register/login (vee‑validate + zod), хранение токенов, авто‑refresh, guard‑middleware, профиль и настройки приватности (opt‑in history, retention).
- Аудит действий (без контента чатов при `saveHistory=false`).
- DoD: защищённые страницы закрыты, happy‑path login→profile работает, ошибки в едином формате `{ error: { code, message } }` и логируются в Sentry.

### Этап 3 — Чат с ИИ + голос (2 недели)

- Сервер: `POST /api/ai/chat` (safety, sessionId), `POST /api/ai/tts`, `POST /api/ai/stt`; idempotency‑keys для команд; таймауты/ретраи провайдеров.
- Фронт: UI чата (текст), TTS (Howler, lazy‑load), STT (микрофон + разрешения), fail‑soft состояния и ретраи.
- Сохранение истории: по умолчанию off; при opt‑in — хранение с гибким retention.
- Безопасность: фильтрация high‑risk тем с мягким редиректом на SOS.
- DoD: диалог RU/EN устойчив, TTS проигрывается, STT корректно распознаёт, деградации не ломают UX.

### Этап 4 — 3D‑аватар (база) (1 неделя)

- Интеграция лёгкого 3D‑вьюера (lazy), состояния загрузки, базовые анимации (мигание/кивок), синхронизация с активностью чата (без лип‑синка в MVP).
- Перфоманс: отключаем при слабых девайсах/низком FPS, тесты на TTI/LCP после включения.
- DoD: аватар отображается стабильно, не ухудшает бюджеты перфоманса.

### Этап 5 — Терапия и привычки, статистика (1–2 недели)

- Сервер: `habits/*`, `therapy/log|stats`; очереди BullMQ для агрегатов статистики (eventually consistent).
- Фронт: экраны `therapy.vue`, `habits.vue`, графики через `vue-chartjs`, состояния loading/empty, валидация ввода.
- DoD: логирование привычек работает, графики корректны, данные не блокируют UI при подсчётах.

### Этап 6 — SOS (0.5 недели)

- Сервер: `GET/POST /api/sos/plan` (ключи i18n), обновляемые ресурсы помощи.
- Фронт: экран с шагами/контактами, доступен из главного меню и из safety‑редиректов в чате.
- DoD: доступность A11y, быстрое открытие, оффлайн‑чтение в MVP+.

### Этап 7 — Биллинг (web) и рефералы (1–1.5 недели)

- Сервер: `GET /api/billing/products`, `POST /api/billing/subscribe`, `POST /api/billing/stripe/webhook`; `referrals/*` (create, stats, payouts/request).
- Фронт: экран `billing.vue` (покупка, статус подписки), реферальный экран/ссылки, отображение начислений.
- Идемпотентность на оплатах, безопасная обработка вебхуков, обновление энтайтлментов пользователя.
- DoD: успешная покупка web, корректная реакция на вебхуки, начисления по рефералам считаются.

### Этап 8 — PWA и мобильные контейнеры (1 неделя)

- PWA: manifest, иконки, базовый offline‑cache (оффлайн‑чтение и черновики — MVP+).
- Capacitor: генерация iOS/Android контейнеров, проверка пушей/хаптики при необходимости, сборки debug.
- DoD: PWA устанавливается, контейнеры собираются и запускаются на девайсах/эмуляторах.

### Этап 9 — Качество, тестирование, Storybook, перфоманс (сквозной + 1 неделя на харднинг)

- Тесты: Vitest юниты для use‑cases/composables; Playwright e2e (базовые сценарии — приоритет этап 2).
- Storybook: библиотека UI‑компонентов (кнопки, поля, диалоги, тосты) + визуальные снапшоты в MVP+.
- Наблюдаемость: Sentry релизные артефакты, мэппинг сорс‑карт; структурные логи сервера.
- Перфоманс: code‑split, lazy тяжёлых модулей (3D/TTS/графики), бюджеты LCP/TTI, оптимизация изображений.
- DoD: зелёные тесты, нет регрессов линтера, бюджеты перфоманса выдержаны.

## Критерии качества (Definition of Done)

- **Фронт**: UX соответствует гайдлам (glass + a11y), локализация RU/EN, формы валидируются (zod), ошибки и клики в Sentry, unit‑тесты на критичные сценарии, TS без `any`.
- **Бэк**: каждый handler тонкий, логика в use‑cases, Zod DTO на вход/выход, логирование и трассировка, тесты (юнит/интеграция), SLA P95 < 200ms на базовых ручках.
- **Контракты**: изменения через `shared/dto/*` с версионированием; нельзя ломать задним числом.

## Управление данными и безопасность

- Приватность по умолчанию: история чатов off (opt‑in), гибкие retention‑периоды.
- Идемпотентность: оплата, генерация, экспорт — через `Idempotency-Key` и таблицу `idempotency_keys`.
- Rate‑limit: per IP/user, агрессивнее на AI/tts/оплатах; ответы `429` с `Retry-After`.
- Хранилище: Postgres (Neon), Redis (Upstash) для кеша и очередей BullMQ, R2 для медиа.

## Метрики и аналитика

- KPI из продуктового ТЗ: активации онбординга, retention D1/D7/D30, средний стрик, доля завершённых задач, конверсия в платёж, ARPPU/LTV, CSAT/NPS.
- События: онбординг старт/финиш, первое сообщение в чате, TTS проигран, STT использован, привычка залогирована, терапия отмечена, покупка успешна, реферальная оплата.

## Риски и снижающие меры

- Риск деградации провайдеров AI/TTS/STT → fail‑soft, ретраи, graceful fallback на текст.
- Производительность 3D → lazy‑загрузка, ability to disable, прогрессивные эффекты.
- Валидация IAP (MVP+) и биллинг → строгая идемпотентность, вебхуки, журнал транзакций.
- Приватность/этика → фильтры высокорискового контента, SOS‑редиректы, возрастные ограничения.

## Post‑MVP (MVP+ и дальше)

- IAP verify (iOS/Android), расширенный 3D (губы/эмоции), сообщества/чаты с модерацией, оффлайн‑кеш PWA (чтение и черновики), интеграции Apple Health/Google Fit, A/B‑платформа, антиспам/модерация.
