# Критичное ТЗ: Оптимизация тарифной сетки для рентабельности

## 🔴 Критическая проблематика

### Текущая модель монетизации

**Тарифные планы:**

- **Basic**: 0₽/месяц (0 минут чата, только уведомления)
- **PRO**: 349₽/месяц (100 минут/неделю ≈ 400 минут/месяц)
- **Premium**: 649₽/месяц (100 минут/неделю ≈ 400 минут/месяц)

### Проблемы текущей модели

#### 1. **Низкая маржа при полном использовании лимита**

**PRO план (349₽/месяц, 400 минут):**

```
Выручка:       349₽/месяц
Расход OpenAI: 400 мин × 0.52₽ = 208₽/месяц
Маржа:         141₽/месяц
Рентабельность: 40% ⚠️
```

**Premium план (649₽/месяц, 400 минут):**

```
Выручка:       649₽/месяц
Расход OpenAI: 400 мин × 0.52₽ = 208₽/месяц
Маржа:         441₽/месяц
Рентабельность: 68% 🟡
```

**Критично:** При 100% использовании лимита маржа PRO составляет всего 40%, что **опасно мало** для SaaS-бизнеса. После вычета инфраструктуры (~50₽/пользователь) реальная прибыль: **~90₽/пользователь (26%)**.

#### 2. **Отсутствие дифференциации между PRO и Premium**

Оба тарифа имеют одинаковый лимит минут (100 минут/неделю), но Premium стоит в 2 раза дороже. Это создает путаницу и снижает ценность Premium.

#### 3. **Риск при массовом использовании**

При масштабировании на 1000 пользователей, если все будут использовать полный лимит:

```
Выручка:  1000 × 349₽ = 349,000₽
OpenAI:   1000 × 400мин × 0.52₽ = 208,000₽
Инфраструктура: ~50,000₽
Чистая прибыль: 91,000₽ (26% маржа) ⚠️
```

#### 4. **Отсутствие защиты от "жадных" пользователей**

Нет механизмов ограничения для пользователей, которые используют весь лимит в первые дни недели.

## 💰 Как работает тарификация OpenAI API

### Модель ценообразования

**Используемая модель: `gpt-4o-mini`**

**Цены за 1M токенов:**

- **Input (входящие токены)**: $0.150 / 1M токенов
- **Output (исходящие токены)**: $0.600 / 1M токенов

### Что считается токенами

**Входящие токены (Input):**

- System промпты (инструкции для модели)
- Memory/summary (контекст прошлых сессий)
- Previous response ID (контекст из OpenAI)
- Все сообщения пользователя
- История диалога

**Исходящие токены (Output):**

- Ответы ассистента
- Сгенерированные чипы (suggested chips)
- Тексты уведомлений

### Расчет стоимости одного запроса

**Средний запрос терапии (~5000 токенов):**

```
Input:  3500 токенов × $0.150 / 1M = $0.000525
Output: 1500 токенов × $0.600 / 1M = $0.000900
─────────────────────────────────────────────
Итого:  ~$0.00143 за сообщение (≈0.13₽)
```

**На 1 минуту диалога (≈3-5 сообщений):**

```
Стоимость: $0.00572 за минуту (≈0.52₽)
```

### Rate Limits (лимиты скорости)

OpenAI использует систему **Tier** для ограничения скорости запросов:

- **Tier 1**: 200K TPM (токенов в минуту) - до ~40 одновременных пользователей
- **Tier 2**: 450K TPM - до ~90 пользователей (разблокируется при трате $50+)
- **Tier 3**: 2M TPM - до ~400 пользователей (разблокируется при трате $1000+)
- **Tier 4**: 10M TPM - до ~2000 пользователей (разблокируется при трате $5000+)

**Важно:** Tier повышается автоматически по мере траты денег. Не нужно платить за Tier отдельно.

### Оптимизации уже реализованные

1. ✅ Уменьшено количество summaries с 10 до 4
2. ✅ Ограничено количество сообщений в контексте до 30
3. ✅ Уменьшен max_output_tokens с 2048 до 1024
4. ✅ Добавлен retry механизм при Rate Limit ошибках

**Результат:** Средний запрос теперь ~2500-3000 токенов вместо 5000 (экономия ~50%).

## 📊 Критерии успеха

### Минимальные требования к рентабельности

1. **Маржа не менее 70%** на всех тарифах при среднем использовании (40-50% лимита)
2. **Маржа не менее 50%** даже при 100% использовании лимита
3. **Четкая дифференциация** между тарифами (минимум 2x разница в лимитах)
4. **Защита от перерасхода** через недельные лимиты

### Метрики для отслеживания

- **ARPU** (Average Revenue Per User): должен быть ≥ 400₽/месяц
- **CAC Payback**: окупаемость привлечения клиента ≤ 2 месяца
- **LTV/CAC**: отношение lifetime value к стоимости привлечения ≥ 3:1
- **OpenAI Cost Ratio**: расход на OpenAI ≤ 15% от выручки

## ⚠️ Критические риски

### Риск 1: Потеря пользователей при изменении цен

**Митигация:**

- Grandfathering для существующих пользователей (сохранить старые цены на 3-6 месяцев)
- Постепенное повышение цен (20% каждые 3 месяца)
- Улучшение продукта параллельно с повышением цен

### Риск 2: Превышение Rate Limits при масштабировании

**Митигация:**

- Мониторинг TPM usage в реальном времени
- Автоматическое переключение на резервные API ключи
- Request queue с token budget
- Оптимизация промптов и контекста

### Риск 3: Низкая конверсия при высоких ценах

**Митигация:**

- A/B тестирование цен
- Улучшение onboarding и демонстрации ценности
- Добавление trial периода для новых пользователей
- Реферальная программа
