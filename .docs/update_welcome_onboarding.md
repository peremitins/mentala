5. Логика шагов

Рекомендуемый порядок шагов: 1. приветствие 2. имя 3. причина прихода 4. возраст 5. пол 6. стиль общения 7. завершение

Почему именно так:
• сначала формируется доверие
• потом идёт лёгкий личный вопрос
• затем собирается главный контекст пользователя
• только после этого спрашиваются технические данные
• ближе к концу настраивается тон общения

Это воспринимается намного естественнее, чем когда после имени сразу спрашивают пол и возраст.

Прогресс-бар:
• показывает только интерактивные шаги анкеты
• приветственный экран и финальный экран в прогресс не входят
• итоговый расчёт для первой итерации: `1 из 5` … `5 из 5`

⸻

6. Что важно изменить в текстах

Все тексты онбординга должны быть:
• мягкими
• короткими
• человечными
• без канцелярита
• без ощущения анкеты
• без излишне рекламных обещаний

Нужно избегать формулировок в стиле:
• давайте быстро настроим приложение
• выберите параметры профиля
• завершите регистрацию

Нужен тон:
• спокойный
• бережный
• простой
• поддерживающий

⸻

Для первой итерации достаточно сделать короткий, но более осмысленный онбординг.

9. Фон welcome-онбординга

Для welcome-онбординга нужен отдельный визуальный слой с обоями, который используется только внутри этого flow и не пересекается с системой фоновых scene приложения.

Что важно зафиксировать:
• текущий синий фон не удаляется — он остаётся базовым слоем и fallback-состоянием
• поверх него в онбординге показывается отдельный onboarding background
• onboarding background берётся из каталога `public/onboarding/welcome`
• выбор между `*-portrait.webp` и обычным `*.webp` должен происходить по той же логике, что и у scene background
• источник истины — ориентация viewport, а не тип устройства: если `height >= width`, сначала пробуем portrait-вариант, иначе базовый
• fallback должен совпадать с scene-логикой: сначала `file-portrait.ext`, затем `portrait-file.ext`, затем базовый файл
• у каждого шага онбординга должен быть свой закреплённый фон, а не случайная картинка
• этот фон не должен использоваться в scene-selection и в основном приложении

Требования к отображению:
• обои должны занимать весь экран по принципу cover
• поверх обоев обязательно накладывается затемняющий overlay, чтобы фон не отвлекал и не бил по глазам
• затемнение должно сохранять читаемость текста, инпутов, кнопок и прогресс-бара на любом шаге
• допустимо использовать мягкий градиентный overlay, а не просто плоскую чёрную заливку
• если картинка не загрузилась или для шага нет ассета, интерфейс должен корректно работать на текущем синем фоне без визуального «провала»

Требования к анимации:
• при переключении шага фон должен меняться плавно, без резкой подмены
• вместе с фоном должен плавно анимироваться и сам блок с вопросом
• переход должен восприниматься спокойно и мягко, без агрессивного параллакса и резких вспышек
• анимация фона и карточки должна быть синхронизирована по времени
• для пользователей с `prefers-reduced-motion` анимации нужно упрощать или отключать

Примечание по ассетам:
• сейчас в каталоге `public/onboarding/welcome` есть 7 наборов обоев (`1..7` и `1-portrait..7-portrait`)
• для первой итерации добавлять восьмой набор не нужно
• финальный экран переиспользует первый фон приветственного экрана (`1.webp` / `1-portrait.webp`)
