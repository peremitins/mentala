# Crysis Prompt — ревью и реализованная логика (LLM always-on)

Дата обновления: 2026-03-04  
Статус: implemented (v3)

## 1. Цель

Обеспечить безопасную обработку сообщений с риском самоповреждения/суицида без short-circuit: LLM отвечает всегда, но получает усиленный safety prompt в зависимости от уровня риска.

## 2. Что реализовано

1. Внедрён server-side детектор кризисных сигналов:
   - `server/application/chat/crisis-protocol.service.ts`
2. Детектор подключён в оба канала чата:
   - `server/interface/api/chat.post.ts`
   - `server/api/chat/stream.post.ts`
3. На основе детекции подмешивается safety `developer`-инструкция через `options.userPrompt`.
4. Введены уровни:
   - `none`
   - `crisis_watch`
   - `crisis_high`
5. Ответ генерируется всегда через LLM (без `return crisis template` и без остановки обычного пайплайна).
6. API-контракт не менялся: отдельное поле `safety` в ответ не добавлялось.

## 3. Поведение в кризисном режиме

### 3.1 CRISIS_HIGH

Модель получает жёсткий safety prompt:

- эмпатия + признание серьёзности;
- обязательная рекомендация немедленно обратиться в экстренные службы;
- рекомендация обратиться к живому человеку;
- максимум 1 вопрос (и этот вопрос — про страну пребывания);
- запрет медсоветов;
- запрет инструкций/обсуждений способов самоповреждения;
- запрет длинных hotline-номеров (включая `8-800...`) и любых неподтверждённых номеров.

Правило локации:

- вопрос о стране обязателен в `crisis_high` даже если локаль уже известна;
- запрещено спрашивать точный адрес, улицу, номер дома, геолокацию;
- пример допустимого вопроса: «В какой стране ты сейчас находишься?».

### 3.2 CRISIS_WATCH

Модель получает мягкий safety prompt:

- бережный тон и деэскалация;
- мягкая рекомендация обратиться за живой помощью при усилении риска;
- те же запреты по адресу/геолокации и harmful-инструкциям.

## 4. Источник номера экстренных служб

Если `user_locale` позволяет определить страну (`en-US`, `ru-RU`, `en_GB` и т.д.), сервер передаёт в safety prompt номер экстренных служб для этой страны (маппинг в `crisis-protocol.service.ts`).

Техническое правило хранения:

- в маппинге хранятся только числовые значения;
- формат данных: `Record<countryCode, string[]>`;
- без языковых слов внутри маппинга (`или`, `or` и т.д.);
- для нескольких номеров формат в prompt: `n1/n2/n3`.
- в ответ допускаются только номера из серверного маппинга (или fallback при неизвестной стране).

Если страна неизвестна:

- модель сначала уточняет только страну;
- одновременно может рекомендовать обратиться в местные экстренные службы (без запроса точного адреса).

## 5. Почему без short-circuit

По текущему решению продукта:

- LLM должна отвечать всегда;
- safety обеспечивается промптовыми guardrails, а не отдельным шаблоном-ответом вне LLM.

## 6. Что важно не путать с SOS

`quick-help/SOS` в MVP остаётся модулем саморегуляции и не является полноценной кризисной службой.
Кризисная логика в этом документе относится к чат-серверу и промпт-инъекции.

## 7. QA (минимум)

Проверяем кейсы:

1. `I want to kill myself` → `crisis_high`
2. `Я хочу убить себя` → `crisis_high`
3. `У меня суицидальные мысли` → `crisis_watch`
4. После высокого риска пользователь пишет только страну (`Россия`) → кризисный контекст сохраняется на ближайшие реплики
5. При неизвестной стране модель спрашивает только страну, не адрес

## 9. Ограничения текущей версии

1. Нет отдельного `safety`-поля в API ответе (по текущему решению не требуется).
2. Номера экстренных служб берутся из локального маппинга; для расширения географии список нужно поддерживать актуальным.
3. Детектор эвристический (regex), без ML-классификатора.
4. Для `crisis_watch` требуется личный контекст (first-person), чтобы не включать кризисный prompt на нейтральные обсуждения темы.
